# ADR-0001：三个扩展点用接口定义，依赖只向内核收敛

- 状态：Accepted
- 日期：2026-11-17
- 相关：`docs/产品定型.md` §6、D1/D2/D15/D18

## 背景

需求横跨三种南向协议（Modbus TCP、Modbus RTU、LoRaWAN/ChirpStack）与一种北向传输（MQTT），且客户云端字段规范尚未提供，后续极可能替换。若内核直接依赖具体库，每次换协议或换云都要改内核。

## 决策

1. 扩展点只有三个，且都是接口：`Driver`（南向协议）、`Channel`（北向传输）、`UplinkAdapter`/`DownlinkAdapter`（物模型）。
2. 依赖方向单向：`cmd → core → interfaces`。内核包不得 import 任何 `drivers/*`、`channels/*`、`adapters/*`。
3. 所有具体实现的构造与装配只发生在 `cmd/collect-code`。
4. 推送型驱动的事件通道 `Events()` 是 `Driver` 的**一等方法**，不是可选接口。拉取型返回 `nil`，内核用 `select` 统一消费，不做类型断言。
5. 适配器按变化原因拆为上行/下行两个接口，一个实现可同时满足两者。

## 后果

- 新增协议 = 新增一个包并实现 `Driver`；内核零改动，且可用假驱动写内核单测。
- 内核必须容忍 `Read` 的空结果与非新鲜样本（见 ADR-0003）。
- 若将来需要运行时加载驱动（插件化），需另行决策；当前编译期注册即可。

## 被否决的方案

- **各包 `init()` 自注册**：初始化顺序隐蔽、无法在测试中替换，且仍会形成包间隐式依赖。
- **单一 `Adapter` 接口**：上行与下行变化原因不同，改一侧会迫使重写另一侧。
- **`EventSource` 可选接口 + 类型断言**：内核需知晓具体接口类型，新增推送协议仍要改内核。
