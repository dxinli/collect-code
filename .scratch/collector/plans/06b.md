## 2. 契约与设计

### 2.1 `simulate` CLI

```text
collect-code simulate [flags]

Flags:
  --manifest <path>         manifest JSON 输出路径（可选；建议测试/脚本显式传入）
  --http-addr <host:port>   模拟器 HTTP 地址，默认 127.0.0.1:0
  --mqtt-addr <host:port>   MQTT broker 地址，默认 127.0.0.1:0
  --capture-capacity <n>    上行捕获环形缓冲容量，默认 1000，范围 1..1000000
  --topic-filter <filter>   云端桩唯一的订阅过滤器，默认 "#"
  -h, --help                打印用法并退出 0
```

- **不提供 `--config`**：06b 的云端桩按“收到的字节”工作，不需要生产配置。06a 需要 profile/寄存器表时再以**新增可选 flag** 的方式接入，不改变 06b 的默认行为。
- **退出码**：`0` 成功/收到 SIGINT/SIGTERM 优雅退出；`1` 启动或运行错误（端口、manifest 写失败等）；`2` 用法错误（未知 flag、缺值、空值、位置参数、非法容量/qos/地址）。
- **stdout/stderr**：成功时不写 stdout（`--help` 除外）；JSON 结构化日志写 stderr（`event=startup|shutdown`，含 `http`、`mqtt`、`manifest`）。mochi 自身日志被配置为写 stderr 的 JSON，级别 `warn`，避免刷屏与污染 stdout。
- **信号**：安装 SIGINT/SIGTERM handler 后再启动监听；收到信号后记录 shutdown、关闭 HTTP 与 broker、释放端口、返回 0。第二次信号恢复默认动作（与 01a 的 `run` 一致）。
- **启动顺序**（保证 manifest 出现时两端已可连接）：
  1. 绑定 MQTT listener（`127.0.0.1:0`，得到实际地址）；
  2. 启动 broker 的 Serve 循环；
  3. 绑定 HTTP listener（`127.0.0.1:0`），启动 `http.Server`；
  4. 原子写 manifest；
  5. 记录 startup 日志，等待取消。
- **地址校验**：`--http-addr`/`--mqtt-addr` 必须是 `host:port`，端口 0..65535；默认 loopback。若用户显式传入非 loopback 地址，启动日志打印一条 `warn`（模拟器无鉴权），但不阻止（测试与特殊联调需要）。
- **与生产 health 隔离**：`simulate` 不加载生产配置，不读取也不绑定 `health.addr`；HTTP 默认 `127.0.0.1:0`，与将来生产的健康端点（默认 `127.0.0.1:9100`）完全独立，也不绑定 8080/1700。
- **端口释放**：关闭时先 `http.Server.Shutdown`（短超时，真实时钟），再 `broker.Close()`；测试断言关闭后 dial 失败。

### 2.2 manifest JSON 契约

`--manifest <path>` 在两端监听成功、HTTP 已开始服务之后写出。写入方式：同目录临时文件 + `fsync` + `rename`，**原子替换**；目标目录必须已存在，不自动 `MkdirAll`。manifest 只写一次，不随运行变化；进程退出后文件保留（它是启动快照）。

06b 示例：

```json
{
  "schema_version": 1,
  "generated_at": "2026-11-20T11:22:33.123456789Z",
  "pid": 4242,
  "http": {
    "base_url": "http://127.0.0.1:39001",
    "host": "127.0.0.1",
    "port": 39001
  },
  "mqtt": {
    "url": "mqtt://127.0.0.1:39002",
    "host": "127.0.0.1",
    "port": 39002,
    "tls": false,
    "protocols": ["3.1.1", "5.0"],
    "topic_filters": ["#"],
    "capture_capacity": 1000
  },
  "endpoints": {
    "captured": "/_sim/captured",
    "invoke": "/_sim/invoke",
    "control": "/_sim/control"
  },
  "control_actions": {
    "global": ["broker_disconnect"]
  },
  "modules": ["mqtt"]
}
```

规则：

- 时间字段统一 `time.RFC3339Nano`；`generated_at` 与 captured 的 `received_at` 都由 Runtime 的可注入 `now func() time.Time` 产出（默认 `time.Now`），测试可注入固定时间，避免 golden/断言抖动。
- `schema_version` 是**整数**，06b 为 `1`。**加法扩展不升版**：新增顶层 section（`modbus`、`chirpstack`）、`endpoints` 新键、`control_actions` 新模块、`modules` 新元素都不破坏 06b 的消费者。删除/改义字段才升到 `2`，并另行评审。
- 消费者必须**按字段名读取、忽略未知字段**；测试**不得**断言 manifest 的完整键集合或逐字节 golden（端口/`generated_at`/`pid` 天然变化）。
- `endpoints` 的键全局唯一（`captured`/`invoke`/`control`；06a 追加 `requests`）。重复注册视为启动错误。
- `control_actions` 以模块名分组，`global` 表示无模块限定的全局动作。这样 06a 的 `modbus.unit_offline` 与 12b 的 `chirpstack.unit_offline` 可以共存，避免全局 action 名冲突。
- `mqtt.url` 直接可用于 `northbound.mqtt.broker`；`http.base_url` 由消费者拼接 `endpoints`。
- `mqtt.topic_filters` 保留为数组；06b 固定一个元素（默认 `["#"]`），为未来多过滤器留位，不改变消费方式。
- 原子性单独测试：一个写者反复原子写、多个读者并发读，任一时刻读到的都是完整合法 JSON；不残留临时文件。

### 2.3 云端桩订阅模型与捕获

- 06b 只建**一个 inline 订阅**（订阅过滤器来自 `--topic-filter`，默认 `#`），不读配置里的 topic 模板。
- 捕获时**跳过**两类报文：
  1. `$SYS/...`（broker 自身遥测）；`#` 会匹配到它们（已实测），必须显式排除。
  2. `pk.Origin == mqtt.InlineClientId`（`inline` 客户端发出的下行），保证 `/_sim/captured` 只表示“收到的上行”。
- 记录结构（按到达顺序，`seq` 从 1 单调递增）：

```json
{
  "seq": 7,
  "topic": "v1/irrigation/VALVE-0001/property/post",
  "payload": {"msg_id": "01J...", "type": "property.post"},
  "qos": 1,
  "retain": false,
  "received_at": "2026-11-20T11:22:40.001234567Z"
}
```

- `received_at` 由注入的 `now` 产出，格式与 manifest 一致（`RFC3339Nano`）。
- `payload` 是**原样字节**的 JSON 表示：字节是合法 JSON 时以 JSON 值返回（对象/数组/数字等），否则退化为 JSON 字符串。这样 07 可直接比对对象；非法 UTF-8/非 JSON 不在采集报文契约内，退化表示仅用于诊断。
- **并发安全**：捕获缓冲由 `sync.Mutex` 保护；订阅回调只做“复制 payload + 追加”，不阻塞 broker。读者在锁内复制切片/记录，锁外编码。
- **容量与背压**：固定容量环形缓冲，默认 1000。满时**丢最旧**并累加 `dropped` 计数；绝不阻塞 broker。响应始终返回 `dropped`，丢弃是可观测的。
- **不做按 topic/设备的服务端过滤**：`GET /_sim/captured` 返回当前全部记录；消费者自行筛选。容量有限，内存有界。`seq` 与 `dropped` 足以支持 07 的顺序/补发断言。

### 2.4 HTTP API 通用约定

- 只监听 `--http-addr`，默认 `127.0.0.1:0`；仅提供 `/_sim/*`，根路径 404。
- 请求/响应均为 JSON；`Content-Type: application/json; charset=utf-8`。请求体上限 1 MiB。
- 成功响应含 `"ok": true`；错误响应为 `{"ok":false,"error":"<message>"}`。
- 400/500 使用 JSON 错误；404/405 允许使用标准库默认文本（测试只断言状态码）。
- `/invoke` 与每个 control action 的处理器使用 `DisallowUnknownFields` 解码自己的字段；control 的中央分发只宽松提取 `module`/`action`，避免误拒各动作的专有字段。
- 无鉴权、无 TLS；仅面向本机测试。

错误表：

| HTTP | 场景 |
|---|---|
| 400 | JSON 解析失败、未知字段、缺必填、`qos` 非 0/1、topic 非法、`duration_ms` 为负或超上限、未知 module/action |
| 404 | 未知路径 |
| 405 | 已知路径、方法不对 |
| 500 | broker 发布失败、内部编码失败 |

### 2.5 `GET /_sim/captured`

响应：

```json
{
  "ok": true,
  "messages": [
    {"seq": 1, "topic": "v1/irrigation/S1/property/post", "payload": {"type": "property.post"}, "qos": 1, "retain": false, "received_at": "2026-11-20T11:22:40.001234567Z"}
  ],
  "dropped": 0
}
```

- `messages` 按 `seq` 升序；空时为 `[]`（不是 `null`）。
- 不提供分页/增量查询（06b 保持最小）；07 可在测试代码里按 `seq`/topic 过滤。

### 2.6 `POST /_sim/invoke`

请求：

```json
{
  "topic": "v1/irrigation/VALVE-0001/service/invoke",
  "payload": {
    "msg_id": "01J...",
    "type": "service.invoke",
    "device_sn": "VALVE-0001",
    "service_id": "set_opening",
    "seq": 17,
    "params": {"opening": 50.0},
    "timeout_ms": 600000,
    "issued_ts": 1763400000000
  },
  "qos": 1,
  "retain": false
}
```

- `topic`：必填，必须是合法 publish topic（无 `+`/`#`，不以 `$SYS` 开头）。**先独立检查 `topic == ""` 并返回 400**，再调用 `mqtt.IsValidFilter(topic, true)`；该函数在 `forPublish=true` 时**不拒绝空串**（v2.7.9 `topics.go` 行为），不能单独承担“非空”校验。
- `payload`：必填的 JSON 值；**原样字节**发布。若是 JSON 对象/数组，就是该值的字节；若希望发布纯文本，请发送 JSON 字符串并按需自行处理引号。06b 不支持 base64 原始二进制。
- `qos`：可选，默认 `1`，只允许 `0`/`1`（与 `docs/contracts/simulator.md` 一致，v1 不支持 QoS 2）。
- `retain`：可选，默认 `false`。
- **不做 `service.invoke` 语义校验**：不检查 `type`/`device_sn`/`seq`/`params`。模拟器是传输对端，不是业务校验器；09/05b 才是校验方，测试也可能故意注入畸形报文。这是刻意选择（见 §7 开放问题 Q3）。
- 响应：

```json
{"ok": true, "topic": "...", "qos": 1, "retain": false, "bytes": 173}
```

- 发布通过 broker 的 inline `Server.Publish` 完成，绕过 ACL（模拟器无 ACL），对订阅者按 MQTT 语义投递。
- `retain=true` 时保留消息生效；06b 不额外清理（进程重启即清空）。

### 2.7 `POST /_sim/control` 与 `broker_disconnect`

请求：

```json
{"action": "broker_disconnect", "duration_ms": 5000}
```

- `action` 必填；可选的 `module` 用于未来多模块动作的命名空间（06b 的 `broker_disconnect` 是 global action，不需要 `module`）。
- 06b 只注册 `broker_disconnect`；未知 action 返回 400。
- `duration_ms` 可选，默认 `0`，范围 `0..86400000`。

`broker_disconnect` 语义（关键设计）：

1. **不停止 listener**：listener 始终绑定原端口，manifest 中的 `mqtt.url` 不变。原因：地址是 `127.0.0.1:0`，停掉再起会换端口，collector 的配置/manifest 全部失效；而真实断线时 broker 端口通常仍在，只是连接被切断。
2. **踢掉已连接客户端**：对该 MQTT listener 上的所有非 inline 客户端调用 `Client.Stop(...)`（直接关闭 TCP，不发送 DISCONNECT），模拟网络中断。inline 客户端与 HTTP 服务不受影响。
3. **可选保持期**：若 `duration_ms > 0`，在踢连接之前把 `hold_until = now + duration_ms` 写入认证 hook；保持期内任何新 `CONNECT` 由 `OnConnectAuthenticate` 返回 `false`，broker 回非成功 CONNACK（实测为 code 5）并关闭连接。
4. **自动恢复**：恢复判定是**惰性**的——每次 `CONNECT` 用注入的 `now()` 与 `hold_until` 比较；过期后自动接受，不需要第二次控制调用，也不启动后台 timer。`duration_ms=0` 表示只踢一次、立即允许重连。
5. **时钟可注入**：broker 持有一个 `now func() time.Time`（默认 `time.Now`）。单元/集成测试注入假时间，先断言保持期内拒绝，再推进时间断言接受，**完全不依赖 sleep**。`hold_until` 与假 `now` 都可能被控制 goroutine 与连接 goroutine 并发访问，必须用 mutex/atomic 保护（`-race` 覆盖）。模拟器不属于 `internal/core`/`internal/drivers`，直接使用时间符合硬约束。
6. **捕获缓冲不清空**：断线前后的消息靠 `seq` 连续观察；补发测试可直接断言断线后的新消息序号更大。
7. **不额外干预 LWT**：`Client.Stop` 关闭 TCP 后 broker 按正常断连路径处理；若客户端自己配置了 LWT，broker 会按 MQTT 语义发送，06b 不断言其内容（LWT 配置属于 05a）。

**auth hook 的强制要求（评审 M1）**：

- mochi 在没有任何 hook 提供对应能力时，对**连接与 ACL 都默认拒绝**：`HookBase.OnConnectAuthenticate` 与 `HookBase.OnACLCheck` 均返回 `false`。只实现 `OnConnectAuthenticate` 会得到“能连上、但 publish/subscribe 全被拒”的 broker。
- 06b 只注册**一个** hook，`Provides` 对 `hooks.OnConnectAuthenticate` 与 `hooks.OnACLCheck` 两个字节都返回 `true`：
  - `OnConnectAuthenticate`：hold 期内返回 `false`，其余时间返回 `true`；
  - `OnACLCheck`：**恒返回 `true`**（hold 期内没有已连接客户端；连接入口由前者拦截）。
- 不得用“allow-all hook + 单独拒绝 hook”的组合：hook 聚合语义是“任一 hook 返回 `true` 即通过”，allow-all 会永久覆盖 hold 拒绝。
- 必须有一条测试：未触发 hold 时，真实客户端 `CONNECT → SUBSCRIBE → PUBLISH` 全部成功（防止 M1 回归）。

响应：

```json
{"ok": true, "action": "broker_disconnect", "disconnected": 1, "hold_until": "2026-11-20T11:22:45.123456789Z"}
```

- `duration_ms=0` 时 `hold_until` 为 `null`。
- 重复调用：覆盖为新的 `hold_until`（取较晚者），并再次踢掉当前连接。

未来动作：06a 用 `module: "modbus"` + `unit_offline`/`unit_slow`/`unit_bad_crc`；12b 用 `module: "chirpstack"` + `queue_full`/`unit_offline`/`delayed_take`。注册表以 `(module, action)` 为键，6b 只实现 global 分发，冲突在启动时报错。

### 2.8 broker 库与版本

- 选择 `github.com/mochi-mqtt/server/v2`，**精确 pin `v2.7.9`**（当前最新 stable，MIT）。
- import 约定：根包名为 `server`，使用别名 `mqtt "github.com/mochi-mqtt/server/v2"`；其余为 `packets "…/packets"`、`listeners "…/listeners"`、`hooks "…/hooks"`，避免别名冲突。
- 已用临时模块实测/源码核对（未改本仓库）：
  - `CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build` 成功，产物为静态 ELF aarch64；amd64 同样成功。
  - **`listeners.NewTCP(listeners.Config{ID:"mqtt", Address:"127.0.0.1:0"})`** + `AddListener` 立即绑定，`Address()` 返回实际端口；用 `Clients.GetByListener("mqtt")` 取连接，显式 ID 避免依赖空串的脆弱行为。
  - `Options.InlineClient=true`；`Server.Subscribe(filter string, subscriptionId int, handler InlineSubFn) error`（**3 参**）能收到真实客户端 publish；`pk.Origin` 标识发布者。
  - **`InlineClientId = "inline"` 在根包**（不在 `packets`），用于过滤 inline 下行。
  - **inline 的 `#` 订阅会匹配 `$SYS/...`**（`gatherInlineSubscriptions` 没有 `$` 守卫，与普通客户端订阅不同），因此捕获时必须显式跳过 `$SYS/`。
  - **`Server.Publish(topic string, payload []byte, retain bool, qos byte)`**：retain 在 qos 前；本计划的 wrapper 是 `Publish(topic, payload, qos, retain)`，内部必须按上游顺序映射。
  - `Client.Stop(err error)` 直接关闭 TCP；客户端重连后同一 client id 可重新 CONNACK 成功（takeover 会清理旧连接）。
  - `Server.Serve()` 启动内部循环后返回；关闭用 `Close()` 释放 listener 与端口。
  - 自定义 hook 在 `OnConnectAuthenticate` 返回 `false` 时，MQTT 3.1.1 客户端收到 CONNACK code 5。
  - mochi 的 hook 默认拒绝连接与 ACL；本实现必须用**同一个 hook 同时提供** `OnConnectAuthenticate` 与 `OnACLCheck`（见 §2.7）。
  - `mqtt.IsValidFilter(topic, true)` 不拒绝空串（见 §2.6），空串需独立校验。
- 传递依赖（以 `go mod tidy` 为准）：预期仅 `github.com/gorilla/websocket v1.5.0` 与 `github.com/rs/xid v1.4.0`；`copier`/`yaml.v3` 只出现在未 import 的 `config`/`hooks/storage` 子包。均为纯 Go，无 cgo。
- 只使用稳定入口：`New/Options/AddHook/Subscribe/AddListener/Publish/Client.Stop/Clients.GetByListener/Close`、`packets` 的只读字段、`listeners`、`hooks` 的接口/常量、`mqtt.IsValidFilter`。不 import `hooks/storage`、`config`、`examples`、`cmd`。
- 不使用其内置 auth/storage/websocket hook；只加一个最小自定义 hook（同时实现连接鉴权与 ACL）。

### 2.9 扩展缝（06a/12a/12b 如何接入而不返工）

`internal/sim` 提供**具体注册方法**，不引入通用插件框架（当前只有一个模块，过早抽象会猜错）：

```go
// Runtime 由 cmd 构造；模块在启动前注册自己的贡献。
func (r *Runtime) Handle(pattern string, h http.HandlerFunc)           // 追加 /_sim 路由
func (r *Runtime) SetEndpoint(name, path string) error                 // manifest.endpoints
func (r *Runtime) SetSection(name string, v any) error                 // manifest 顶层 section
func (r *Runtime) RegisterControl(module, action string, fn ControlFunc) error // (module, action) → handler

// ControlRequest 由中央 /_sim/control handler 传入；Body 是完整原始 JSON，
// 动作处理器自行用 DisallowUnknownFields 解自己的字段。
type ControlRequest struct {
    Module string
    Action string
    Body   json.RawMessage
}
type ControlFunc func(ControlRequest) (any, error)
// 返回 BadRequest(...) 包装的错误 → HTTP 400；其他错误 → HTTP 500。
```

- 06b 的 `MQTTBroker` 在 `Register(r)` 中调用：
  - `SetSection("mqtt", ...)`、`SetEndpoint("captured"/"invoke"/"control", ...)`
  - `RegisterControl("", "broker_disconnect", ...)`
  - `Handle("GET /_sim/captured", ...)`、`Handle("POST /_sim/invoke", ...)`
- 06a：`SetSection("modbus", ...)`、`SetEndpoint("requests", "/_sim/requests")`、`Handle("GET /_sim/requests", ...)`、`RegisterControl("modbus", ...)`。
- 12a：`SetSection("chirpstack", ...)`、gRPC listener 地址写入 section、`RegisterControl("chirpstack", ...)`。
- 12b：复用 `MQTTBroker.Publish(topic string, payload []byte, qos byte, retain bool)` 产生 ChirpStack 上行；wrapper 内部映射到上游 **`server.Publish(topic, payload, retain, qos)`**（参数顺序不同）。inline 发布的 `Origin=="inline"`，不会进入 `/_sim/captured`；若通过真实 MQTT 客户端发布，会被捕获（见 §9 交接说明）。
- `sim.Run` 是唯一装配点：按顺序构造 runtime、broker、未来模块，调用它们的 `Register`，再启动。**模块生命周期不抽接口**；等出现第二个模块且有共性时再抽象。
- 测试隔离规则：06b 的测试只断言自己拥有的 section/endpoint/action；新增 section 不得要求改 06b 测试。
