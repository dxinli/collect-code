### 0.1 v2 修订摘要（按独立评审）

独立评审结论为 `approve with required changes`；v2 逐条处理如下：

1. **事务错误传播（blocker）**：§5.7 所有 `db.Update`/`db.View` 伪代码改为显式检查返回错误，闭包内每次 bbolt 调用也检查错误；`DeleteExpired` 失败（ctx/JSON/IO）一律返回 `(0, err)`，不得把回滚事务的 `count` 当成功返回。补 `DeleteExpiredCanceledContextLeavesRecords` 与 bbolt 专属 corrupt-record 回滚测试。
2. **两实现可观测一致性（blocker）**：新增 §4.12/§4.13——`SaveSnapshot(nil)` 两实现都归一化为空数组、`LoadSnapshot` 返回 `found=true` + 非 nil 空切片；`Property.Quality` 视为 opaque string 原样往返，`Record.Phase` 由 Store 维护并在 decode 时校验 `accepted/final`。补 `SaveSnapshotNilIsFoundEmpty`、`UnknownQualityIsOpaque`。
3. **DeleteExpired 边界**：明确去重设备集合、`Bucket` nil guard、删除阶段 ctx 检查、corrupt record fail-fast；补同设备多条、空库、重开、取消、空子 bucket 清理测试。
4. **Close/并发/损坏防御**：补 `CloseWhileWritesInFlight`、第二个实例打开超时（白盒 `open` 短超时）、0600/0750 权限、`schema_version`/`last_seq` 长度错误、`DeleteExpired` 损坏记录回滚等测试。
5. **契约套件生命周期**：`Run` 在每个子测试内注册 `t.Cleanup`，并用假 harness 自测清理次数；补 zero time、`Data` 内 `time.Time`、nil vs 空 map、`Property.Value` 嵌套拷贝、未知 Quality、重复 device 等测试。
6. **静态检查**：`check_store_root` 增加“非标准库 import 白名单”；新增 `app`/`cmd` 的 `.Deps` 禁止 `memory`/`storetest`；required 目录补 memory/storetest/bbolt；自检注入到非 `_test.go`。
7. **依赖时序**：评审担心“`go get` 未写入 x/sys 构建期 hash，bbolt 首次 import 的提交不可编译”。实测（临时模块）`go get go.etcd.io/bbolt@v1.4.3` 已写入 bbolt 与 `golang.org/x/sys` 的 h1 与 `/go.mod`，直接 import 构建 `exit=0`；因此该担忧不成立。仍采纳“bbolt 首次 import 的提交（§12 提交 7）执行 `go mod tidy`”以去掉 `// indirect` 标记，并把 `go.mod/go.sum` 变更放进同一提交。
8. **规范更新改为必需**：Close 后行为、JSON 精度、`SaveSnapshot(nil)`、空 device、`DeviceState.LastSeq` 与水位关系、corrupt 策略都必须写入 `docs/contracts/store.md`，不能只靠包文档。
9. **并发测试规模**：8×50 降为 8×20，保留最终一致性断言，避免 `-count=10` 在 CI 上过慢。
10. **顺序口径修正**：`LoadDevices` 顺序不保证；`LoadSnapshot` 保留输入顺序，写成单一契约。

## 2. 包布局与依赖方向

### 2.1 目录

```text
internal/interfaces            # 02a 冻结，本 ticket 不改
internal/store/
  storetest/                   # 共享契约测试套件（普通包，只被 *_test.go import）
    storetest.go
  memory/                      # 测试用内存实现
    memory.go
    memory_test.go
  bbolt/                       # 生产实现
    store.go
    store_test.go              # 黑盒：契约套件 + schema/打开测试
```

不新增共享 codec 包。理由：内存实现不落盘，直接对 `interfaces.*` 做 JSON 往返即可获得与 bbolt 完全一致的**可观测**语义（`Data`/`Value` 的数字类型、time 的单调/时区归一）；bbolt 需要稳定的磁盘字段名，因此它自己持有带 JSON tag 的 DTO。两边都由契约套件强制同一种 JSON 语义，重复的只有少量 `json.Marshal/Unmarshal` 调用，不值得为它增加一个必须被静态检查放行的包。若将来需要二进制编码或跨语言读取，再单独评审 codec，不在 02b 预埋。

### 2.2 依赖方向

```text
internal/interfaces            # 纯契约；不 import 本模块任何包
      ^
      │
      ├── internal/store/storetest     # 只 import interfaces + 标准库
      │        ^
      │        └── 只被 memory_test.go / bbolt/store_test.go 引用（test-only）
      │
      ├── internal/store/memory        # interfaces + 标准库；不得 import bbolt
      │
      └── internal/store/bbolt         # interfaces + go.etcd.io/bbolt + 标准库
                   │
                   └── go.etcd.io/bbolt

internal/core/*  ──> interfaces.Store（生产代码绝不 import 具体 store）

```

- `internal/core` 已由 `check-deps.sh` 的 `common` 规则禁止 import `internal/store/*`；本 ticket 不改变该规则。
- `memory` 被 `core` 的 `_test.go` 引用是允许的：`go list .Deps` 不含测试专用 import，现有脚本也按此口径。

### 2.3 编译期断言

```go

```

契约套件只通过 `interfaces.Store` 调用，不依赖具体实现类型（harness 的 `Reopen` 除外，见 §7）。

## 3. Store 语义落地（逐条对应冻结注释）

冻结来源：`internal/interfaces/store.go` 的 `Store` 注释与 `errors.go` 的三个哨兵。下表是 02b 的唯一实施口径，两个实现必须逐条一致。

| 方法/语义 | 落地方式 | 契约测试 |
|---|---|---|
| `BeginAccepted` 写入 `{device, seq, service_id, at, phase=accepted}` | bbolt：单个写事务内“检查 + Put 记录 + 推进水位”；memory：锁内“检查 + 编码 + 写入 + 推进水位” | `BeginAcceptedAndLookup` |
| 同一 `(device, seq)` 已存在（accepted 或 final）→ `ErrAlreadyAccepted`，不得覆盖 | 检查原始字节是否存在，不 decode、不更新 `ServiceID/At/Data`；水位不变 | `BeginAcceptedDuplicateIsRejected` |
| `Finish` 未知记录 → `ErrRecordNotFound` | 先查 `(device, seq)`；不存在立即返回，不创建记录 | `FinishUnknownRecordIsRejected` |
| `Finish` 已 final → `ErrAlreadyFinal`，不修改终态字段 | decode 后检查 `Phase==PhaseFinal`；是则返回哨兵，事务回滚/不写入 | `FinishAlreadyFinalIsRejected` |
| `Finish` 成功 → `phase=final`，写入 `code/msg/data/final_at`，保留 `accepted_at/service_id` | 同一写事务读改写；`FinalAt=rec.At` | `FinishCompletesAcceptedRecord` |
| `Lookup` 不存在 → `found=false, err=nil` | bbolt `Get==nil`；memory map 未命中 | `LookupMissingReturnsNotFound` |
| `LastSeq` 无记录 → `0, nil` | 独立水位 bucket/map；缺失即 0 | `LastSeqStartsAtZeroAndIsMonotonic` |
| `LastSeq` 是已受理 `seq` 的单调水位；`BeginAccepted` 成功后不小于该值；只增不减 | `BeginAccepted` 同事务内 `if rec.Seq > current { Put(rec.Seq) }`；duplicate 不推进 | 同上 + `BeginAcceptedDuplicateIsRejected` |
| `LastSeq` 经 `DeleteExpired` 后仍保留 | 水位独立存放，`DeleteExpired` 只碰记录，不碰水位 | `LastSeqSurvivesDeleteExpired` |
| `LoadDevices` 空集合 → 空切片（非 nil）+ nil | `make([]DeviceState, 0)`；不返回 nil | `LoadDevicesEmptyReturnsEmptySlice` |
| `SaveDevices` 按 device upsert，不删除未出现的 device | 单事务逐个 Put；不执行任何 Delete | `SaveDevicesUpsertsWithoutDeleting` |
| `LoadSnapshot` 不存在 → `nil,false,nil`；存在 → 副本 | decode 新切片返回；不返回内部引用 | `LoadSnapshotMissingReturnsNotFound`、`ReturnedValuesAreCopies` |
| `SaveSnapshot` 整设备原子替换 | 单事务单次 Put 覆盖整个 device 的 JSON 数组；不是逐属性合并 | `SaveSnapshotReplacesWholeDevice` |
| `DeleteExpired` 只删 `phase=final && FinalAt.Before(before)`；accepted 永不自动删；返回条数 | 单写事务扫描全部记录，收集后删除；严格 `Before`（相等保留）；水位不动 | `DeleteExpiredOnlyFinalStrictlyBefore`、`DeleteExpiredKeepsAcceptedRecords`、`DeleteExpiredReturnsDeletedCount` |
| 所有方法接受 ctx，取消时尽快返回 | 入口检查 `ctx.Err()`；扫描/删除循环内周期检查；已取消时不做任何写入 | `CanceledContextReturnsPromptly`、`DeleteExpiredCanceledContextLeavesRecords` |
| `Close` | 见 §4.5 决策；推荐幂等 + Close 后返回 `ErrClosed` | `CloseIsIdempotent`、`OperationsAfterCloseReturnErrClosed` |
| `Property.Quality` | 视为 opaque string：不校验、不转换，两实现原样往返 | `UnknownQualityIsOpaque` |
| `Record.Phase` | Store 自写自读，decode 只接受 `accepted`/`final`；未知值视为磁盘损坏并返回错误（memory 无公开路径产生未知值，行为差异不可观测） | bbolt 专属 `CorruptRecordIsRejected` |
| `SaveSnapshot(nil)` | 两实现都归一化为空数组；`LoadSnapshot` 返回 `found=true` + 非 nil 空切片（§4.12） | `SaveSnapshotNilIsFoundEmpty` |
| 事务失败 | 任一 ctx/JSON/IO 错误 → 事务回滚并返回错误；`DeleteExpired` 返回 `(0, err)`，不得把回滚的删除数当成功 | `DeleteExpiredCanceledContextLeavesRecords`、bbolt 专属 `DeleteExpiredCorruptRecordRollsBack` |
| corrupt record | `Lookup`/`LoadDevices`/`DeleteExpired` 解码失败即 fail-fast 返回错误，不跳过、不猜测 | 同上 |

补充约定（写入 `storetest` 包文档，不修改冻结接口）：

1. **顺序**：`LoadDevices` 的返回顺序不构成契约，契约测试排序后比较；`LoadSnapshot` 保留 `SaveSnapshot` 的输入顺序（两实现都存 JSON 数组/切片，测试固定这一点）。
2. **时间**：持久化只保留时刻，不保留单调时钟与 `time.Location` 名称；契约用 `Time.Equal` 比较，禁止 `==`/`reflect.DeepEqual` 直接比较 `time.Time`。零值 `time.Time{}` 必须能往返（`DeviceState.LastSuccessAt` 未成功时为 `time.Time{}`）。
3. **JSON 语义**：`Record.Data` 与 `Property.Value` 经 JSON 往返；数字统一解码为 `float64`，`nil` 保持 `nil`，嵌套对象/数组为 `map[string]any`/`[]any`，`Data` 内的 `time.Time` 会变成 RFC3339 字符串。契约用 JSON 语义比较，不比较 Go 具体数字类型。
4. **JSON 数字精度**：`Record.Data`/`Property.Value` 中绝对值超过 `2^53` 的整数经 `any` 解码为 `float64` 会丢精度；typed 字段 `Seq`/`LastSeq` 仍以 `uint64` 写入/解码，不受影响。调用方若需要在 `Data`/`Value` 中保留大整数，必须先转字符串。
5. **输入前置条件**：`device` 必须非空（配置校验保证；bbolt 对空 bucket key 返回 `ErrBucketNameRequired`，memory 不保证相同错误）；`seq` 由云端从 1 起分配，Store 不额外校验 `seq`。空 device 不属于冻结契约，契约测试不使用；store 合同与包文档写明该前置条件。
6. **`SaveDevices` 与水位**：`DeviceState.LastSeq` 只是设备状态记录中的一个字段，`SaveDevices` 原样存储；`Store.LastSeq(ctx, device)` 只读幂等水位。两者由 core（17b）负责保持一致，Store 不做隐式同步（见 §4.11）。
7. **写失败原子性**：`SaveDevices` 与 `DeleteExpired` 在一个事务/一次锁内完成；JSON 编码失败、ctx 取消或 bbolt 调用失败时不留下部分写入。
8. **`SaveDevices` 输入内重复 device**：同一调用内后者覆盖前者（按切片顺序），其他 device 不受影响；两实现一致。
9. **corrupt record**：bbolt 读到无法 decode 的记录时 fail-fast（返回错误、事务回滚），不静默跳过；这是磁盘损坏/跨版本的可见诊断路径。
10. **零值 `FinalAt`**：`DeleteExpired` 严格按冻结语义 `FinalAt.Before(before)` 执行，不对零值做特殊判断；调用方（09/10）必须用注入 Clock 填写 `FinalAt`。契约测试固定正 cutoff 下零值 `FinalAt` 被删除的字面行为。

## 4. 需要拍板的边界（A/B + 推荐）

以下每一项都**不替用户拍板**；推荐仅表示实现计划默认按推荐项展开。用户可逐项选择，计划 v3 记录最终决定。

### 4.1 内存实现放哪

- **A（推荐）**：`internal/store/memory`，普通包，文档标明“测试用，只被 `_test.go` 依赖”。与 `internal/store/bbolt` 对称，符合 02a 计划 §2.1 的目录预留；core 的 L1 测试可直接 import 它。
- **B**：`internal/testutil/memorystore`。更贴近 ADR-0004 “测试用内存实现”的字面，且现有 `check-deps` 已禁止 core/drivers import `testutil`；但与 bbolt 不对称，且偏离 02a 已写下的包路径。
- **C**：放在 `internal/store/bbolt` 的 `_test.go` 里。无法跨包复用，03a/03b/09/10 会重复实现。

**推荐 A。代价**：`memory` 在生产目录中，需要靠静态检查与包注释防止误用；现有 `common` 规则已经禁止 core/drivers import `internal/store/*`，本 ticket 再补 store 内部规则。

### 4.2 内存实现的“重开”语义

- **A（推荐）**：memory `Close` 只把句柄标记为 closed，不清空内部数据；提供**测试专用、非 `interfaces.Store` 成员**的 `(*Store).Reopen()` 清除 closed 标志。契约 harness 的 `Reopen` 调用 `Close` 后 `Reopen`，随后 `Store()` 返回同一实例。对契约而言“重开后数据仍在”成立。
- **B**：把持久数据抽成导出的 `*Data`，由 harness 持有，`Reopen` 用 `memory.NewFrom(data)` 创建新实例。更接近 bbolt“新对象、同一份持久数据”，但为了测试暴露内部数据结构，API 污染更大。
- **C**：memory `Close` 为 no-op，`Reopen` 也为 no-op。最简单，但无法测试 Close 后行为，也与 bbolt 语义不一致。

**推荐 A。代价**：memory 的 `Reopen` 是测试专用导出方法，必须在包注释中明确“不属于 `interfaces.Store`”；bbolt harness 的 `Reopen` 则是真正的 close + 重新 `Open` 文件。两者在契约层等价。

### 4.3 序列化格式与类型漂移契约

- **A（推荐）**：统一使用 **JSON 语义**。bbolt 用显式 DTO + 稳定 snake_case JSON tag 落盘；memory 直接对 `interfaces.*` 做 JSON 往返（不落盘）。两边都得到：
  - `Data`/`Value` 中的 `int/uint` → `float64`，嵌套对象/数组 → `map[string]any`/`[]any`；绝对值超过 `2^53` 的整数会丢精度（typed 的 `Seq/LastSeq` 不受影响）；
  - `time.Time` 字段只保留时刻，丢失单调时钟与 location 名称；零值可往返；
  - `nil` 保持 `nil`，空 map/空 slice 与 nil 可区分。
  契约测试用“分别 `json.Marshal` 后比较字节”的 JSON 语义比较；同时显式断言 `Data["int"]` 为 `float64`，把漂移写进契约。02b/10 的回放比较必须复用同一规则，禁止 `reflect.DeepEqual`。
- **B**：二进制/gob 编码。能保留更多 Go 类型，但依赖 Go 类型身份，跨版本不稳定，调试不可读；`any` 的具体类型仍会漂移。
- **C**：bbolt 用 JSON，memory 直接返回调用方传入的 Go 值（只做 map 深拷贝）。实现更简单，但调用方会观察到两个实现返回的 `int` vs `float64` 差异，违背“行为一致”。

**推荐 A。代价**：所有调用方必须接受 JSON 数字语义；`Data` 内的 `time.Time` 不再是 `time.Time`。收益是两实现可观测行为完全一致、磁盘格式可读、与北向 JSON 报文天然对齐。

### 4.4 bbolt 版本

规划时 `go list -m -versions` 可见的最新版本为 **v1.5.0**（2026-06-03，`go 1.25.0`）；本机模块缓存已有 **v1.4.3**（2025-08-19，`go 1.23`）与 v1.3.11（2024-08-20，`go 1.22`）。三者对 `Open/DB/Tx/Bucket/Options/ForEachBucket` 的用法一致（已核对源码）。

- **A（推荐）**：固定 **v1.4.3**。成熟度高于 1.5.0，缓存已有、可离线复现；`go 1.23` 要求对本仓库 1.27.4 无压力；间接依赖只有 `golang.org/x/sys v0.29.0`（实测 `go mod tidy` 后 `go.mod` 仅新增 bbolt + x/sys）。
- **B**：固定 **v1.5.0**。`go list -m -versions` 可见的最新稳定版（规划时）；要求 `go >= 1.25`（本仓库满足），`golang.org/x/sys v0.45.0`。注意 v1.5.0 的模块图还带 `tool` 指令与 x/tools、x/perf、x/mod、go-moremath 等依赖，`go.sum` 明显更大；本机模块缓存没有 x/sys v0.45.0，选 B 需要联网。代价是采用较新的 minor `.0` 版本，需在边缘设备上重新验证。
- **C**：v1.3.11。可用但过旧，无收益，不推荐。

**推荐 A。代价**：错过 1.5.0 的修复；升级只需改一行 `require` + `go mod tidy`，可在后续单独评审。若用户要求“总是最新稳定版”，选 B，本计划的设计、API 用法与测试不变。

### 4.5 Close 与 Close 后行为

- **A（推荐）**：`Close()` 幂等；首次成功后，后续调用返回 nil；Close 后所有带 ctx 的方法返回 `fmt.Errorf("...: %w", interfaces.ErrClosed)`，不再触碰 bbolt DB / 内部数据。bbolt 用 `sync.RWMutex` 保护 `db` 指针，Close 取写锁，方法取读锁，避免 Close 与在途事务竞态。
- **B**：`Close()` 幂等，但 Close 后行为不定义（直接透传 bbolt 的 `ErrDatabaseNotOpen`，memory 可能继续可用）。契约不测试 Close 后调用。
- **C**：Close 后允许继续使用（memory no-op；bbolt 自动重开）。语义复杂，且与“释放资源”直觉冲突。

**推荐 A。代价**：这是对冻结 `Store` 接口的**补充行为约定**（不改签名/类型），必须写入 `docs/contracts/store.md` 与 `storetest` 文档；若用户认为 02a 冻结范围不应扩展，选 B，并删除 `OperationsAfterCloseReturnErrClosed` 与 `CloseIsIdempotent` 之外的 Close 后断言（Close 幂等本身仍保留）。

### 4.6 LastSeq 是否独立物化

- **A（推荐）**：独立水位存储。bbolt 用顶层 `last_seq` bucket（device → 8 字节大端 uint64），memory 用 `lastSeq map[string]uint64`；`BeginAccepted` 在同一事务/锁内按 `max(current, rec.Seq)` 更新；`DeleteExpired` 完全不碰它。
- **B**：每次 `LastSeq` 从剩余记录重算最大值。实现简单，但 `DeleteExpired` 删掉最大 `seq` 的 final 记录后水位会回退，直接违反冻结注释“survives DeleteExpired”；若再引入“已删除记录的水位墓碑”，本质仍是物化，只是更复杂。
- **C**：用 `DeviceState.LastSeq` 兼作水位。`SaveDevices` 与 `BeginAccepted` 两处写同一值，容易互相覆盖，且 device 状态可能被 17b 对账删除，不可靠。

**推荐 A。代价**：多一个 bucket/map 与一次 Put，但 `BeginAccepted` 本来就是写事务，增量可忽略；换来明确、可测的单调水位。

### 4.7 key 布局

- **A（推荐）**：
  ```text
  meta        schema_version -> uint64 BE(1)
  records     <device>/ (嵌套 bucket)
                <seq 8B BE> -> recordDTO JSON
  last_seq    <device> -> uint64 BE
  devices     <device> -> deviceDTO JSON
  snapshots   <device> -> []propertyDTO JSON
  ```
  只有 records 用嵌套 bucket（每设备一个），因为需要按 seq 有序且避免 device 字符串与分隔符冲突；devices/last_seq/snapshots 都是“每个 device 一个值”，扁平 key 最简。
- **B**：全部扁平 + 复合 key（device 长度前缀 + device + seq 8B BE）。只需一个 records bucket 的 cursor 即可扫描所有记录，但 key 编码/解码多一层，容易写出边界错误；device 长度前缀也增加了与未来查询方式的耦合。
- **C**：所有内容都嵌套 bucket（snapshots/<device>/<property-key>）。逐属性更新方便，但 02b 只需要“整设备原子替换”，会引入不必要的删除/重建复杂度。

**推荐 A。代价**：`DeleteExpired` 需要两层循环（先收集设备名，再逐设备扫描），代码量略多；但 device 语义清晰、无 key 拼接歧义，且删除空设备子 bucket 也容易。

### 4.8 快照表示

- **A（推荐）**：`snapshots` 中 device → 一个 JSON 数组（`[]propertyDTO`）。整设备替换就是一次 `Put`，天然原子；快照预算 ≤1 MB（台账 E5），单值完全可承受；加载时一次 decode。
- **B**：device → 嵌套 bucket → property key → JSON。可以逐属性更新，但“整设备替换”需要先删除旧 bucket 再重建，事务内虽然也原子，但代码更多、空值/顺序语义更绕。
- **C**：device → 多个独立顶层 key（device + property）。key 编码复杂，不推荐。

**推荐 A。代价**：不能局部更新单个属性（当前没有该需求）；每次读写整个快照（预算内可接受）。

### 4.9 是否扩展静态检查

- **A（推荐）**：扩展 `scripts/check-deps.sh`，新增 `check_store_root`：
  - 对 `internal/store/*` 的**直接 import**，本模块依赖只允许 `internal/interfaces`；
  - 非标准库 import（路径含 `.`）白名单：只允许 `internal/interfaces`，`bbolt` 额外允许精确的 `go.etcd.io/bbolt`；这样 `golang.org/x/sys`、任意 `github.com/...`、`go.etcd.io/bbolt/...` 子包都会被拒绝；
  - 新增 `check_root internal/app` 与 `check_root cmd`，用 `.Deps` 禁止 `internal/store/memory` 与 `internal/store/storetest`（允许 `internal/store/bbolt`），确保测试实现不进入生产闭包；
  - 把 `internal/store/memory`、`internal/store/storetest`、`internal/store/bbolt` 加入脚本顶部的 required 目录检查（该提交在三个包都已存在之后）。
- **B**：不改脚本，靠评审。风险是未来 core 或 bbolt 误 import memory/storetest，或 memory 误 import bbolt，CI 不会发现。
- **C**：升级为 `go/ast` 分析器。能力更强，但当前仓库只有 shell 脚本先例，新增维护成本，不解决 02b 的主要风险。

**推荐 A。代价**：脚本多约 35 行；`go list` 失败必须显式失败而不是静默通过；用“临时注入错误 import → 脚本必须失败 → 还原”的方式自检（见 §13）。

### 4.10 父目录是否创建

- **A（推荐）**：`Open` 在 `bbolt.Open` 前执行 `os.MkdirAll(filepath.Dir(path), 0o750)`。首次部署即使 `/var/lib/collect-code` 不存在也能启动；测试用 `t.TempDir()` 的子目录也自然成立。
- **B**：要求父目录已存在（由 systemd `StateDirectory=` 或安装脚本创建），`Open` 只打开文件。部署更“显式”，但首次启动/测试会多一个前置条件。

**推荐 A。代价**：Store 会创建目录；权限固定 0750（已有目录不会被修改）。若部署规范要求目录必须由 systemd 创建，可选 B，并在错误信息中提示路径。

### 4.11 SaveDevices 与 LastSeq 水位的关系

- **A（推荐）**：`SaveDevices` 只 upsert `DeviceState`（包括其中的 `LastSeq` 字段），**不修改**幂等水位；`Store.LastSeq` 只由 `BeginAccepted` 推进。两者语义不同，由 17b/core 负责让 `DeviceState.LastSeq` 与水位一致。
- **B**：`SaveDevices` 发现 `state.LastSeq > watermark` 时顺带推进水位。看似更一致，但会让“设备状态保存”隐式产生幂等副作用，且违反冻结注释“LastSeq 是已受理 seq 的水位”的单一来源。

**推荐 A。代价**：调用方若期望两者自动同步会失望；通过包文档与 `SaveDevicesDoesNotChangeLastSeqWatermark` 测试固定该行为，避免误解。

### 4.12 `SaveSnapshot(nil)` 与 `LoadSnapshot` 的 found 语义

- **A（推荐）**：`SaveSnapshot(nil)` 等价于 `SaveSnapshot([]Property{})`。两实现都归一化为空数组；随后 `LoadSnapshot` 返回 `found=true`、非 nil 空切片、`err=nil`。“设备有快照但内容为空”与“设备从未保存过快照”（`nil,false,nil`）是两种不同状态。
- **B**：`SaveSnapshot(nil)` 表示删除该设备快照；`LoadSnapshot` 返回 `nil,false,nil`。语义也自洽，但需要 bbolt `Delete`，且与“整设备替换”的单 Put 设计不一致。
- **C**：原样存 `null`，`LoadSnapshot` 返回 `found=true`、nil 切片；两实现若不统一，会出现 nil vs 空切片差异，且调用方无法区分。

**推荐 A。代价**：调用方不能再用 nil 表示“删除快照”；当前没有删除快照的需求。该约定必须写入 `docs/contracts/store.md`，并用 `SaveSnapshotNilIsFoundEmpty` 固定。

### 4.13 `Quality` / `Phase` 的读取校验

- **A（推荐）**：`Property.Quality` 是调用方输入的 opaque string，Store 不校验、不转换，原样往返（与冻结类型 `Quality string` 一致，允许未来新增质量值）；`Record.Phase` 是 Store 自己维护的状态，decode 时只接受 `accepted`/`final`，未知值视为磁盘损坏/跨版本并返回错误。memory 没有公开路径产生未知 Phase，因此两实现对合法输入的观测行为完全一致。
- **B**：两者都在 decode 时严格校验。会拒绝调用方保存任意 `Quality` 值，改变 `SaveSnapshot` 的可接受输入，且与“Quality 是 wire-visible 枚举、02b 不新增枚举校验”的现有口径冲突。
- **C**：两者都不校验。bbolt 读到损坏的 Phase 时会把它当普通字符串返回，违反 `RecordPhase` 的二值语义，错误更难诊断。

**推荐 A。代价**：Quality 的语义完全由调用方/配置保证；Phase 的校验只存在于 bbolt 的 decode 路径，需要 corrupt-record 测试覆盖。

## 5. bbolt 实现设计

### 5.1 包 API

```go
package bbolt

import (
	"context"
	"time"

	"github.com/dxinli/collect-code/internal/interfaces"
	bolt "go.etcd.io/bbolt"
)

type Store struct {
	mu     sync.RWMutex
	db     *bolt.DB
	closed bool
}

func Open(path string) (*Store, error)
func open(path string, lockTimeout time.Duration) (*Store, error) // 白盒测试用；Open 固定 5s
func (s *Store) Close() error
// 其余方法实现 interfaces.Store。
```

- 返回 `*Store` 而不是 `interfaces.Store`，便于未来扩展与测试；调用方可赋给接口。
- `Open` 是唯一公开构造入口；没有 `New`/全局单例。一个进程同一个 `state.db` 只应打开一个 `*Store`（bbolt 文件锁；第二实例在 `Timeout` 后失败）。
- `open` 不导出，仅供同包白盒测试缩短锁超时；外部测试只使用 `Open`。

### 5.2 打开流程与文件选项

```text
1. path == "" → error
2. os.MkdirAll(filepath.Dir(path), 0o750)
3. bolt.Open(path, 0o600, &bolt.Options{Timeout: lockTimeout})
4. ensureSchema(db)（所有 bucket/Put 错误都要返回）
5. 失败则 db.Close()，返回错误
```

- `Open(path)` 等价于 `open(path, 5*time.Second)`；白盒测试用 `open(path, 200*time.Millisecond)` 验证第二个实例在锁超时后失败。

- **文件权限**：`0o600`；父目录 `0o750`。
- **Timeout=5s**：另一进程持有锁时快速失败，而不是无限等待。锁超时是基础设施超时，不是业务时间；Store 不注入 `Clock`。ADR-0003 的时间规则只约束 `internal/core/*` 与 `internal/drivers/*`。
- **fsync**：保持 bbolt 默认 `NoSync=false`、`NoFreelistSync=false`、`NoGrowSync=false`；每次 `Update` 提交即 fsync，满足 ADR-0004 的事务 1 语义。
- **不设置** `ReadOnly`、`Mlock`、`PageSize`、`InitialMmapSize`、自定义 `FreelistType`；使用默认值，避免在边缘设备上引入未验证的 mmap 行为。
- bbolt 默认 logger 保留；02b 不做日志注入。
- `state.db` 必须位于支持 mmap 与文件锁的本地文件系统；网络文件系统不在支持范围（写入 §14 风险）。

### 5.3 schema 版本

- 顶层 `meta` bucket，key `schema_version`，value 为 **8 字节大端 uint64**，当前 `1`。
- `ensureSchema` 在单个 `db.Update` 中执行，并**返回并检查所有 bbolt 调用的错误**：
  1. 若 `meta` bucket 不存在：
     - 若任何已知业务 bucket（records/last_seq/devices/snapshots）已存在 → 视为无版本的外来/损坏库，返回错误；
     - 否则视为新库，创建五个 bucket，写入 `schema_version=1`。
  2. 若 `meta` 存在但 `schema_version` 缺失 → 返回“缺少 schema_version”错误。
  3. `schema_version` 的 value 长度必须恰好为 8 字节；否则返回错误，**不得直接 `binary.BigEndian.Uint64` 导致 panic**。
  4. 若版本 ≠ 1 → 返回“不支持的 schema version”错误。
  5. 版本 = 1 时，`CreateBucketIfNotExists` 补齐缺失的已知 bucket（容忍空库被部分初始化）；每个调用都检查错误。
- 不做迁移；未来版本升级必须新 ticket。
- 错误信息包含路径与版本号，便于现场诊断。
- `ensureSchema` 失败时事务回滚，`Open` 关闭 DB，不留下半初始化状态；bbolt 事务保证不会出现“写了 meta 没写 bucket”的半状态。

### 5.4 bucket/key/value 布局

| bucket | key | value | 备注 |
|---|---|---|---|
| `meta` | `schema_version` | 8B BE uint64 = 1 | 版本控制 |
| `records` | `<device>`（嵌套 bucket） | — | 每设备一个子 bucket |
| `records/<device>` | `<seq>` 8B BE | `recordDTO` JSON | seq 按字节序即数值序 |
| `last_seq` | `<device>` | 8B BE uint64 | 单调水位；DeleteExpired 不碰 |
| `devices` | `<device>` | `deviceDTO` JSON | upsert |
| `snapshots` | `<device>` | `[]propertyDTO` JSON | 整设备替换 |

- 记录 key 使用 `encoding/binary.BigEndian.PutUint64`；不使用十进制字符串（会破坏字节序数值序）。
- 设备名直接作为 bucket key/key：配置保证非空；长度受 bbolt key 上限约束，设备 SN 远小于上限。
- 不为每个设备单独建 `records` 之外的 bucket；只有 records 用嵌套 bucket。
- `DeleteExpired` 删除记录后，若某设备子 bucket 已空，删除该子 bucket（用 `Cursor().First()==nil` 判断，避免依赖 `Stats()` 在事务内的准确性）；这不影响水位。
- 所有 value 都是 bbolt 事务内的临时 `[]byte`；decode 必须在事务内完成，绝不把 `Bucket.Get` 返回的切片带出事务。

### 5.5 DTO 与 JSON tag（磁盘格式契约）

```go
type recordDTO struct {
	Device     string         `json:"device"`
	Seq        uint64         `json:"seq"`
	ServiceID  string         `json:"service_id"`
	Phase      string         `json:"phase"`
	AcceptedAt time.Time      `json:"accepted_at"`
	FinalAt    time.Time      `json:"final_at"`
	Code       int            `json:"code"`
	Msg        string         `json:"msg"`
	Data       map[string]any `json:"data"`
}

type deviceDTO struct {
	Device        string    `json:"device"`
	Online        bool      `json:"online"`
	LastSuccessAt time.Time `json:"last_success_at"`
	LastSeq       uint64    `json:"last_seq"`
	UpdatedAt     time.Time `json:"updated_at"`
}

type propertyDTO struct {
	Key     string `json:"key"`
	Value   any    `json:"value"`
	Unit    string `json:"unit"`
	Quality string `json:"quality"`
	TS      time.Time `json:"ts"`
}
```

- **不使用 `omitempty`**：保证 `data:null` 与 `data:{}` 可区分，避免磁盘格式随零值静默变化。
- `Phase` 在 DTO 中用 `string`，decode 后只接受 `accepted`/`final`；未知值返回错误（磁盘损坏/跨版本），见 §4.13 A。
- `Quality` 在 DTO 中保持 `string`，视为 opaque：不校验、不转换，原样往返；memory 与 bbolt 一致（§4.13 A）。
- 字段名一旦发布即为磁盘契约；`TestBboltOnDiskSchema` 直接打开 DB 断言这些 key/tag 存在，防止改名不报错。
- 时间使用 `time.Time` 的默认 `RFC3339Nano` JSON：保留纳秒与偏移，丢失单调时钟与 location 名称；零值 `time.Time{}` 编码为 `0001-01-01T00:00:00Z` 并能往返；契约用 `Equal`。
- `Data`/`Value` 必须是 JSON 可编码值；`func/chan/complex/NaN/Inf` 会返回 `json.UnsupportedValueError`，整个事务回滚/内存不写入。`Data`/`Value` 中绝对值超过 `2^53` 的整数经 `float64` 解码会丢精度（§3 补充约定 4）。
- `SaveSnapshot(nil)` 在编码前归一化为 `[]propertyDTO{}`，磁盘值为 `[]` 而不是 `null`；`LoadSnapshot` 对缺失 key 返回 `nil,false,nil`，对存在的 `[]` 返回 `found=true` + 非 nil 空切片（§4.12 A）。

### 5.6 事务边界

| 方法 | 事务 | 说明 |
|---|---|---|
| `BeginAccepted` | 1 个 `Update` | 检查存在性 + Put 记录 + 推进水位；三者同事务，避免“记录写了水位没写”或反之 |
| `Finish` | 1 个 `Update` | 读记录 + 检查 phase + 修改 + Put；全部同事务 |
| `Lookup` | 1 个 `View` | 只读；事务内 decode |
| `LastSeq` | 1 个 `View` | 只读；缺失返回 0 |
| `LoadDevices` | 1 个 `View` | 只读；逐个 decode |
| `SaveDevices` | 1 个 `Update` | 先在锁内编码全部 state（失败则不进入事务），再在一个事务内 upsert |
| `LoadSnapshot` | 1 个 `View` | 只读；一次 decode |
| `SaveSnapshot` | 1 个 `Update` | 先编码整设备数组，再单次 Put 覆盖 |
| `DeleteExpired` | 1 个 `Update` | 先收集待删 key，再删除；同事务 |
| `Close` | 无事务 | 取写锁，关闭 DB |
| `ensureSchema` | 1 个 `Update` | `Open` 时执行 |

- 使用 `db.Update`/`db.View`，不使用 `db.Batch`（Batch 会重试闭包，幂等检查/水位逻辑不适合隐式重试）。
- bbolt 写事务串行；并发写不会 panic，只会按 bbolt 锁顺序执行。
- `SaveDevices`/`DeleteExpired` 的原子性来自单事务，不是接口冻结语义的额外要求，但两实现保持一致。

### 5.7 各方法伪代码

所有方法统一形状：先 `checkCtx`，再取锁并检查未关闭，最后调用 bbolt；**必须接收并返回 `db.Update`/`db.View` 的错误**，闭包内每个 bbolt 调用也检查错误：

```text
func (s *Store) <method>(ctx context.Context, ...) (...) {
    if err := checkCtx(ctx); err != nil { return zero, err }
    s.mu.RLock(); defer s.mu.RUnlock()
    if err := s.checkOpen(); err != nil { return zero, err }
    err := s.db.Update(func(tx *bolt.Tx) error { ... })
    if err != nil { return zero, err }   // 回滚后不得返回部分结果
    ...
}
```

`checkCtx` 用非阻塞 `select` 检查 `ctx.Done()`；`ctx == nil` 视为 `context.Background()`（防 panic，不依赖调用方）。

**BeginAccepted**

```text
checkCtx; RLock; checkOpen
err := s.db.Update(func(tx) error {
    if err := checkCtx(ctx); err != nil { return err }
    records := tx.Bucket(records); if records == nil { return fmt.Errorf("missing records bucket") }
    rb, err := records.CreateBucketIfNotExists([]byte(rec.Device)); if err != nil { return err }
    key := seqBE(rec.Seq)
    if rb.Get(key) != nil { return errAlreadyAccepted }
    value, err := json.Marshal(recordDTO{Device: rec.Device, Seq: rec.Seq, ServiceID: rec.ServiceID,
        Phase: "accepted", AcceptedAt: rec.At})
    if err != nil { return fmt.Errorf("encode accepted record: %w", err) }
    if err := rb.Put(key, value); err != nil { return err }
    wmb := tx.Bucket(lastSeq); if wmb == nil { return fmt.Errorf("missing last_seq bucket") }
    wm, err := readWatermark(wmb, rec.Device); if err != nil { return err }
    if rec.Seq > wm {
        if err := wmb.Put([]byte(rec.Device), seqBE(rec.Seq)); err != nil { return err }
    }
    return nil
})
if err != nil { return err }
return nil
```

- `readWatermark(bucket, device)` 读取设备水位，缺失返回 0，value 长度必须为 8（否则返回错误）。
- 存在性检查只看字节，不 decode；duplicate 不覆盖、不更新水位。
- 水位读取在同一事务内；bbolt 写事务本身串行。

**Finish**

```text
checkCtx; RLock; checkOpen
err := s.db.Update(func(tx) error {
    if err := checkCtx(ctx); err != nil { return err }
    records := tx.Bucket(records); if records == nil { return errRecordNotFound }
    rb := records.Bucket([]byte(rec.Device)); if rb == nil { return errRecordNotFound }
    key := seqBE(rec.Seq); raw := rb.Get(key)
    if raw == nil { return errRecordNotFound }
    old, err := decodeRecord(raw); if err != nil { return err }
    if old.Phase == PhaseFinal { return errAlreadyFinal }
    old.Phase = PhaseFinal; old.FinalAt = rec.At; old.Code = rec.Code; old.Msg = rec.Msg; old.Data = rec.Data
    value, err := json.Marshal(old); if err != nil { return fmt.Errorf("encode final record: %w", err) }
    return rb.Put(key, value)
})
if err != nil { return err }
return nil
```

- 保留 `ServiceID`、`AcceptedAt`、`Device`、`Seq`；不改变水位。

**Lookup / LastSeq / LoadDevices / LoadSnapshot**

```text
checkCtx; RLock; checkOpen
var out ...
err := s.db.View(func(tx) error {
    if err := checkCtx(ctx); err != nil { return err }
    ... Get + decode；不存在时设置 found=false/zero 并 return nil ...
})
if err != nil { return zero, false/nil, err }
```

- `LoadDevices` 用 `make([]interfaces.DeviceState, 0)`，`ForEach` 逐个 decode；空 bucket 返回非 nil 空切片；decode 错误立即返回。
- `LoadSnapshot` 未命中返回 `nil,false,nil`；命中 decode 成新切片；存储值为 `null` 时返回非 nil 空切片（`found=true`，§4.12）。
- `LastSeq` / `readWatermark` 的 value 长度必须为 8，否则返回错误（磁盘损坏），不得 panic。
- 除 `last_seq` 中缺少某个 device 的键按 0 处理外，`records`/`devices`/`snapshots` bucket 缺失都视为 schema 损坏并返回错误，不静默返回空结果。

**SaveDevices**

```text
checkCtx; RLock; checkOpen
encoded := make([]struct{device string; value []byte}, 0, len(states))
for _, st := range states {
    if err := checkCtx(ctx); err != nil { return err }
    value, err := json.Marshal(deviceDTO{Device: st.Device, Online: st.Online,
        LastSuccessAt: st.LastSuccessAt, LastSeq: st.LastSeq, UpdatedAt: st.UpdatedAt})
    if err != nil { return fmt.Errorf("encode device state: %w", err) }
    encoded = append(encoded, {st.Device, value})
}
err := s.db.Update(func(tx) error {
    if err := checkCtx(ctx); err != nil { return err }
    b := tx.Bucket(devices); if b == nil { return fmt.Errorf("missing devices bucket") }
    for _, e := range encoded {
        if err := checkCtx(ctx); err != nil { return err }
        if err := b.Put([]byte(e.device), e.value); err != nil { return err }
    }
    return nil
})
if err != nil { return err }
return nil
```

- 先在锁内编码全部 state；任一编码失败则不进入事务、不写入。
- 不删除未出现的 device；输入内重复 device 后者覆盖前者；不碰 `last_seq`。

**SaveSnapshot**

```text
checkCtx; RLock; checkOpen
if props == nil { props = []interfaces.Property{} }   // §4.12 A：归一化，避免存 null
dtos := make([]propertyDTO, 0, len(props))
for _, p := range props { dtos = append(dtos, propertyDTO{Key: p.Key, Value: p.Value,
    Unit: p.Unit, Quality: string(p.Quality), TS: p.TS}) }
value, err := json.Marshal(dtos); if err != nil { return fmt.Errorf("encode snapshot: %w", err) }
err = s.db.Update(func(tx) error {
    if err := checkCtx(ctx); err != nil { return err }
    b := tx.Bucket(snapshots); if b == nil { return fmt.Errorf("missing snapshots bucket") }
    return b.Put([]byte(device), value)
})
if err != nil { return err }
return nil
```

- 单次 Put 覆盖旧值，整设备原子替换；`nil` 与空切片都存为 `[]`。

**DeleteExpired**

```text
checkCtx; RLock; checkOpen
type recKey struct{ device string; seq uint64 }
count := 0
err := s.db.Update(func(tx) error {
    if err := checkCtx(ctx); err != nil { return err }
    records := tx.Bucket(records); if records == nil { return nil }
    var toDelete []recKey
    affected := map[string]struct{}{}
    if err := records.ForEachBucket(func(device []byte) error {
        if err := checkCtx(ctx); err != nil { return err }
        dev := string(device)
        rb := records.Bucket(device); if rb == nil { return nil }
        return rb.ForEach(func(k, v []byte) error {
            if err := checkCtx(ctx); err != nil { return err }
            rec, err := decodeRecord(v); if err != nil { return err }  // fail-fast
            if rec.Phase == PhaseFinal && rec.FinalAt.Before(before) {
                if len(k) != 8 { return fmt.Errorf("corrupt seq key") }
                toDelete = append(toDelete, recKey{dev, binary.BigEndian.Uint64(k)})
                affected[dev] = struct{}{}
            }
            return nil
        })
    }); err != nil { return err }

    for _, item := range toDelete {
        if err := checkCtx(ctx); err != nil { return err }
        rb := records.Bucket([]byte(item.device)); if rb == nil { continue }
        if err := rb.Delete(seqBE(item.seq)); err != nil { return err }
        count++
    }
    for dev := range affected {
        if err := checkCtx(ctx); err != nil { return err }
        rb := records.Bucket([]byte(dev))
        if rb != nil && rb.Cursor().First() == nil {
            if err := records.DeleteBucket([]byte(dev)); err != nil { return err }
        }
    }
    return nil
})
if err != nil { return 0, err }   // 事务已回滚；count 不得外泄
return count, nil
```

- accepted 永不删除；`FinalAt.Before(before)` 严格小于，相等保留。
- 先收集再删除，避免在 `ForEach` 中边遍历边修改；`affected` 是去重集合，每个设备只做一次空 bucket 检查。
- 任一 decode/IO/ctx 错误 → 整个事务回滚，返回 `(0, err)`；不跳过损坏记录（§3 补充约定 9）。
- 空 store 返回 `(0, nil)`；第二次调用返回 0。

### 5.8 Close、并发与错误

```go
var (
	errClosed        = fmt.Errorf("bbolt store: %w", interfaces.ErrClosed)
	errRecordNotFound = fmt.Errorf("bbolt store: %w", interfaces.ErrRecordNotFound)
	errAlreadyAccepted = fmt.Errorf("bbolt store: %w", interfaces.ErrAlreadyAccepted)
	errAlreadyFinal   = fmt.Errorf("bbolt store: %w", interfaces.ErrAlreadyFinal)
)
```

- 所有方法入口：`if ctx == nil { ctx = context.Background() }`；`ctx.Err()` 非 nil 直接返回该错误。之后取 `s.mu.RLock()`，检查 `s.closed`，再检查一次 `ctx.Err()`。
- `Close` 取 `s.mu.Lock()`；若已关闭返回 nil；否则置 `closed=true`，`db.Close()`，`db=nil`，返回 Close 错误。首次 Close 的错误不缓存；第二次返回 nil。
- 使用 RWMutex 而不是 Mutex：多个读事务可并行；Close 等待所有在途事务结束，防止 bbolt 在 Close 后仍被调用。该性质由 `CloseWhileWritesInFlight`（`-race`）验证：并发 Begin/Finish/Lookup 与 Close 不 panic、不死锁；Close 之后发起的方法返回 `ErrClosed`。
- `db.Close()` 内部会等待/拒绝在途事务；我们的锁保证不会与我们的方法并发。
- **ctx 的限制**：bbolt 的 `Begin`/`Update` 获取写事务锁不能被 ctx 打断；如果另一个写事务正在 fsync，取消的调用会等它完成。02b 的写事务都很短（单记录/单 Put），`DeleteExpired` 的扫描/删除内部有 ctx 检查；这是可接受的“尽快返回”，不承诺实时抢占。写入 §14 风险。
- 错误一律用 `%w` 包装哨兵，调用方 `errors.Is` 可判。JSON/IO 错误用 `%w` 保留底层错误。
- bbolt 默认 logger 保留：它可能向 stderr 输出非结构化错误/致命信息。02b 不接入项目 logger（不在本 ticket 装配 app）；该限制写入 §14 风险，17b 接线时再决定是否注入。Store 自身返回的错误已由调用方结构化记录。

### 5.9 打开期与运行期的错误分类

- `Open` 错误：空路径、父目录创建失败、文件锁超时（bbolt `ErrTimeout`）、schema 不兼容、IO 错误。
- 方法错误：ctx 取消、`ErrClosed`、三个 store 哨兵、JSON 编码/解码错误、底层 IO 错误。
- 不新增导出哨兵；schema 错误用普通 `fmt.Errorf`（调用方只需启动失败并记录日志）。

## 6. 内存实现设计

### 6.1 数据结构

```go
type Store struct {
	mu        sync.RWMutex
	records   map[string]map[uint64][]byte // device -> seq -> record JSON
	lastSeq   map[string]uint64
	devices   map[string][]byte            // device -> device JSON
	snapshots map[string][]byte            // device -> []property JSON
	closed    bool
}

func New() *Store
func (s *Store) Close() error
func (s *Store) Reopen() // 测试专用，不属于 interfaces.Store
```

- 值统一存 JSON `[]byte`，与 bbolt 一样“写入即编码、读取即解码”。这样：
  - 返回的 `Data`/`Value` 类型漂移与 bbolt 完全一致；
  - 调用方修改传入的 map/切片或返回的对象都不会影响内部状态；
  - `LoadSnapshot` 的“返回副本”天然成立；
  - `Quality` 原样往返（opaque），与 bbolt 一致；`Phase` 只由 Store 写 `accepted`/`final`，无公开路径产生未知值。
- 不使用 `map[string]interfaces.Record` 直接存 Go 值，否则 memory/bbolt 会观察到 `int` vs `float64` 差异。
- `SaveSnapshot(nil)` 与 bbolt 一样先归一化为 `[]interfaces.Property{}`，存 `[]`；`LoadSnapshot` 对存在的 `[]` 返回 `found=true` + 非 nil 空切片（§4.12 A）。
- `DeleteExpired` 用 `map[string]struct{}` 记录受影响设备，删除后再检查空集合；与 bbolt 的去重清理口径一致。

### 6.2 并发与原子性

- `sync.RWMutex`：读方法 `RLock`，写方法 `Lock`。
- `BeginAccepted`/`Finish`：锁内完成检查 + 编码 + 写入 + 水位更新；不存在部分写入。
- `SaveDevices`：同一把写锁内编码全部 state 到临时切片；全部成功后再一次性写入 map；任一失败不写入。
- `DeleteExpired`：锁内先收集待删 `(device, seq)`，再统一删除；ctx 取消时返回错误且不删除任何记录。
- `Close`：写锁，置 `closed=true`，不清空 map。
- `Reopen`：写锁，置 `closed=false`；若本来未关闭则 no-op。

### 6.3 Close 后行为

按 §4.5 A：所有带 ctx 方法在入口检查 `closed`，返回包装 `interfaces.ErrClosed` 的错误（零值 + error）；`Close` 幂等。`Reopen` 后可继续使用，数据仍在。若用户选择 B，则移除 closed 检查与相关契约测试。

### 6.4 与 bbolt 的差异边界

| 方面 | memory | bbolt |
|---|---|---|
| 持久化 | 仅进程内，Close 不丢数据 | 文件；Close 后重开 |
| Reopen | 同一实例清除 closed | 关闭并重新 `Open` 同一路径 |
| 顺序 | map 遍历顺序随机 | bucket key 字节序 |
| 错误文本 | `memory store: ...` | `bbolt store: ...` |
| 哨兵 | 相同 `interfaces.Err*` | 相同 `interfaces.Err*` |
| JSON 可见行为 | 相同 | 相同 |

契约测试只使用接口与哨兵，不依赖错误文本、顺序或具体类型。

## 7. 共享契约测试套件

### 7.1 位置与 API

`internal/store/storetest/storetest.go`，普通包，只 import `interfaces` + 标准库：

```go
package storetest

// Harness abstracts one store plus its persistence lifecycle.
type Harness interface {
	Store() interfaces.Store
	// Reopen closes the current store and returns one over the same persisted
	// data. The caller must call Store() afterwards.
	Reopen(t *testing.T)
	// Cleanup releases resources. Run registers it with t.Cleanup.
	Cleanup(t *testing.T)
}

type Factory func(t *testing.T) Harness

// Run executes the full Store contract against the harness returned by factory.
// Each subtest gets a fresh harness.
func Run(t *testing.T, factory Factory)
```

- `Run` 必须在**每个 `t.Run` 的子测试闭包内**调用 `factory(t)` 并注册 `t.Cleanup(func(){ h.Cleanup(t) })`；不得在父 `t` 上只注册最后一个 harness 的清理。`Cleanup` 必须可在已 Close/Reopen 失败的情况下安全重复调用。
- `storetest` 自带 `TestRunCleansUpEachSubtest`：用假 harness 记录 Cleanup 次数，断言每个子测试都清理且总次数正确。
- 套件不调用 `t.Parallel`（共享同一 store 的并发语义由具体测试自己管理）。
- 套件不 import `memory`/`bbolt`，因此不会被具体实现反向依赖；静态检查也会拒绝。
- 套件不假设 `LoadDevices` 顺序，devices 比较前按 `Device` 排序；`LoadSnapshot` 保留输入顺序。

### 7.2 子测试清单（也是验收映射）

| 子测试 | 断言 |

| `ReturnedValuesAreCopies` | 修改传入 map/切片或返回对象，不影响再次读取（record Data、DeviceState、snapshot、`Property.Value` 中的嵌套 map/slice） |
| `JSONRoundTripSemantics` | `Data`/`Value` 的 `int` → `float64`；嵌套 map/slice 正确；nil 保持 nil；JSON 语义相等 |
| `TimesCompareByInstant` | 所有 time 字段 `Equal` 原值；不依赖 location/monotonic |
| `ZeroTimesRoundTrip` | `AcceptedAt/FinalAt/LastSuccessAt/UpdatedAt/TS` 的 `time.Time{}` 往返后仍 `Equal` 零值 |
| `DataTimeBecomesString` | `Data["t"]=time.Time{}`、`Property.Value=time.Time{}` 读回为 RFC3339 字符串；两实现一致 |
| `NilVsEmptyMapSlice` | `Data` 的 nil vs `{}`、`Property.Value` 的 nil vs `{}` 可区分；快照的 nil 按 §4.12 归一化 |
| `CanceledContextReturnsPromptly` | 每个带 ctx 方法在已取消 ctx 下返回 `errors.Is(err, context.Canceled)`；不发生写入 |
| `CloseIsIdempotent` | 连续 Close 都返回 nil（§4.5 A） |
| `OperationsAfterCloseReturnErrClosed` | Close 后每个方法返回 `errors.Is(err, interfaces.ErrClosed)`（§4.5 A） |
| `CloseWhileWritesInFlight` | 并发 Begin/Finish/Lookup 与 Close：不 panic、不死锁；Close 后发起的方法返回 `ErrClosed`（`-race`） |
| `ConcurrentWritesAndReadsDoNotPanic` | 8×20 个 goroutine 并发 Begin/Finish/Lookup/SaveDevices/SaveSnapshot；无 panic、无竞态、最终状态正确 |

> 若用户对 §4.5 选 B，则移除 `CloseIsIdempotent`（或保留仅测 Close 两次不 panic）与 `OperationsAfterCloseReturnErrClosed`；若对 §4.11 选 B，则移除 `SaveDevicesDoesNotChangeLastSeqWatermark` 并改写 `SaveDevicesUpsertsWithoutDeleting` 的相关断言；若对 §4.12 选 B，则把 `SaveSnapshotNilIsFoundEmpty` 改为断言 `nil,false,nil`；若对 §4.13 选 B，则把 `UnknownQualityIsOpaque` 改为断言保存/读回错误。

### 7.3 JSON/时间比较辅助

```go
// jsonEqual compares two values by their JSON encoding. encoding/json sorts
// map keys, so this compares JSON semantics, not Go type identity.
// Both helpers call t.Helper() and t.Fatalf on marshal/type errors.
func jsonEqual(t *testing.T, want, got any) bool

func timeEqual(t *testing.T, want, got time.Time) bool // got.Equal(want)

func sortDevices([]interfaces.DeviceState)
```

- `jsonEqual` 分别 `json.Marshal` 后 `bytes.Equal`；对 `int(1)` 与 `float64(1)` 都编码为 `1`，通过；marshal 失败时 `t.Fatalf`，不返回假阳性。
- `JSONRoundTripSemantics` 另外显式断言 `reflect.TypeOf(got.Data["int"]) == reflect.TypeOf(float64(0))`，把数字漂移固定下来。
- 禁止在 `Data/Value` 上使用 `reflect.DeepEqual`；禁止在 `time.Time` 上用 `==`。
- 契约套件文档写明：02b/10 的回放比较必须使用同样的 JSON 语义；`Data`/`Value` 中超过 `2^53` 的整数会丢精度。

### 7.4 并发测试细节

```text
workers = 8, perWorker = 20
每个 worker：device = "dev-<w>"，seq = 1..20
  BeginAccepted → Finish
并发 reader：Lookup/LastSeq/LoadDevices/LoadSnapshot
并发 saver：SaveDevices/SaveSnapshot（每 worker 自己的 device）
WaitGroup 等待；错误经带缓冲 channel 汇总，不在 goroutine 里 t.Fatal
结束后：每个 device 的 20 条记录都是 final；LastSeq()==20；devices/snapshot 正确
```

- 该测试在 `make test-race` 下运行；bbolt 的内部并发由 bbolt 保证，memory 由 RWMutex 保证。
- 规模从 8×50 降为 8×20：bbolt 每次写事务都 fsync，8×20 已足以覆盖并发/竞态，`-count=10` 也不会在 CI 上过慢。
- 测试不并发调用 `Close`（Close 语义由 `CloseWhileWritesInFlight` 单独覆盖），避免把“关闭中调用”混入并发写验收。

## 9. 静态检查加固

### 9.1 `scripts/check-deps.sh` 变更

在现有 `check_root` 之外新增 `check_store_root`，用**直接 import**（`go list -f '{{range .Imports}}{{println .}}{{end}}'`）做白名单，而不是只看传递闭包：

```bash
check_store_root() {
	local root="$1" allow_bbolt="$2"
	[ -d "$root" ] || return 0
	local pkgs
	if ! pkgs="$(go list ./"$root"/... 2>&1)"; then
		echo "FAIL: go list ./$root/... failed: $pkgs" >&2
		fail=1
		return
	fi
	while IFS= read -r pkg; do
		[ -n "$pkg" ] || continue
		local imports bad bad_external
		if ! imports="$(go list -f '{{range .Imports}}{{println .}}{{end}}' "$pkg")"; then
			echo "FAIL: go list $pkg failed" >&2
			fail=1
			continue
		fi
		# 本模块直接依赖只允许 interfaces。
		bad="$(printf '%s\n' "$imports" | grep -F "${MODULE}/" | grep -vxF "${MODULE}/internal/interfaces" || true)"
		if [ -n "$bad" ]; then
			echo "FAIL: $pkg imports module packages other than interfaces:" >&2
			printf '%s\n' "$bad" >&2
			fail=1
		fi
		# 非标准库 import（路径含点）白名单：只允许 interfaces；bbolt 额外允许精确根包。
		# 这会拒绝 golang.org/x/sys、任意 github.com/... 与 go.etcd.io/bbolt/... 子包。
		if [ "$allow_bbolt" = "yes" ]; then
			bad_external="$(printf '%s\n' "$imports" | grep -E '\.' \
				| grep -vxF "${MODULE}/internal/interfaces" | grep -vxF 'go.etcd.io/bbolt' || true)"
		else
			bad_external="$(printf '%s\n' "$imports" | grep -E '\.' \
				| grep -vxF "${MODULE}/internal/interfaces" || true)"
		fi
		if [ -n "$bad_external" ]; then
			echo "FAIL: $pkg imports forbidden external packages:" >&2
			printf '%s\n' "$bad_external" >&2
			fail=1
		fi
	done <<< "$pkgs"
}

check_store_root internal/store/memory no
check_store_root internal/store/bbolt yes
check_store_root internal/store/storetest no

# 生产装配不得引入测试用实现（bbolt 是允许的）。
app_forbidden="${MODULE}/internal/store/(memory|storetest)(/|$)"
check_root internal/app "$app_forbidden"
check_root cmd "$app_forbidden"
```

- `.Imports` 不含 `_test.go` 的 import，所以 `memory_test.go` import `storetest`、`bbolt/store_test.go` import `storetest` 不会误报。
- 本模块直接依赖白名单是“精确等于 `interfaces`”，因此：
  - memory → bbolt、storetest → memory/bbolt、bbolt → memory/storetest 全部失败；
  - `internal/core/*` → 任何 store 仍然由现有 `common` 规则失败；
  - bbolt 只能直接 import `interfaces` 与 `go.etcd.io/bbolt`（加标准库）；`golang.org/x/sys` 或其它第三方包会被外部 import 白名单拒绝。
- app/cmd 的 `.Deps` 检查保证 `internal/store/memory` 与 `internal/store/storetest` 不进入生产二进制；`internal/store/bbolt` 仍可被 17b 装配。
- 脚本顶部 required 目录加入 `internal/store/memory`、`internal/store/storetest`、`internal/store/bbolt`（该提交在三个包都已存在之后），确保包被删除时检查不会静默跳过。
- `go list` 失败显式 `fail=1`，不静默通过。
- 不使用网络；只分析本地包。

## 14. 风险与回滚

| 风险 | 影响 | 缓解 |
|---|---|---|
| JSON 往返导致 `int→float64`、time 丢失单调/location | 02b/10 回放比较失败 | 契约统一 JSON 语义；`JSONRoundTripSemantics`/`TimesCompareByInstant` 固定；store 合同写明禁止 `reflect.DeepEqual`/`==` |
| `Data`/`Value` 中超过 `2^53` 的整数丢精度 | 云端收到的数值错误 | store 合同/包文档明确；需要大整数时调用方先转字符串；不引入 `json.RawMessage` |
| `Data` 内的 `time.Time` 变成字符串 | 调用方按 `time.Time` 断言失败 | 包文档与 store 合同明确：只有 typed 时间字段保持时刻；`Data` 只保证 JSON 原生形状 |
| memory 与 bbolt 对同一输入返回不同类型 | “行为一致”验收失败 | memory 也做 JSON 往返；Quality opaque、Phase 校验口径一致；契约显式断言 `float64`/`SaveSnapshot(nil)` |
| Close 与在途事务竞态 | bbolt panic/错误 | RWMutex：方法读锁、Close 写锁；Close 幂等；Close 后返回 `ErrClosed`；`CloseWhileWritesInFlight` 覆盖 |
| 事务错误被吞、回滚后返回部分 count | 契约谎报删除成功 | 所有 `Update/View` 返回值检查；`DeleteExpired` 失败返回 `(0, err)`；corrupt-record 回滚测试 |
| ctx 取消不能打断 bbolt 写锁等待 | 取消不够“及时” | 写事务短；入口/扫描/删除循环检查 ctx；文档说明限制；不承诺实时抢占 |
| bbolt 文件锁被另一进程持有 | Open 挂起或失败 | `Open` 固定 `Timeout=5s`；白盒 `open` 短超时测试；快速失败并记录路径 |
| schema 版本不兼容/无版本旧库/长度损坏 | 启动失败或 panic | `meta/schema_version` 长度=8 校验；不兼容场景与 corrupt 长度有测试；不做隐式迁移 |
| memory 被生产代码 import | 生产使用非持久存储 | `check-deps.sh` 的 store 白名单 + app/cmd `.Deps` 检查；包注释 |
| bbolt 误 import memory/storetest 或第三方包 | 依赖方向破坏 | 静态检查直接 import 白名单（含非标准库路径） |
| `DeleteExpired` 全表扫描 | 记录多时延迟 | final 记录受 TTL 限制；扫描/删除内检查 ctx；单写事务；后续 10 可优化 |
| bbolt 文件只增不减 | `state.db` 增长超 E5 预算 | 删除释放页供 bbolt 复用；不做压缩（非目标）；后续按 E5 观测 |
| bbolt 默认 logger 输出非结构化 stderr | 与项目日志约定不一致 | 本 ticket 不改 bbolt logger；文档记录，17b 装配时再评估注入；Store 自身错误由调用方结构化记录 |
| `go.sum` 变大/静态编译失败 | CI 红 | 只引入 bbolt+x/sys（v1.4.3）；`make build-all verify-static` 双架构验证 |
| 父目录权限不符合部署规范 | 启动失败 | 0750 创建；已有目录不改；文档提示 systemd `StateDirectory` 场景；权限测试 |
| 网络文件系统上 mmap/文件锁不可靠 | 运行异常 | 文档明确只支持本地文件系统 |
| 空 device / 空 key | bbolt 自身错误 vs memory 行为差异 | 配置保证非空，写入 store 合同前置条件；不纳入冻结契约 |
| 测试并发不稳定 | CI 偶发红 | 并发测试只用确定性唯一键；读允许 accepted/final；no `t.Fatal` in goroutine；`-race`；规模 8×20 |
| 用户对 A/B 的选择改变行为 | 返工 | §4 明确列出；v3 记录决策后再实现；实现中变更回到计划评审 |

**回滚策略**：

- 依赖提交可独立回滚；回滚后需一并回滚 bbolt 提交，memory/契约套件不受影响。
- 契约套件与 memory 可独立保留；若 bbolt 实现有问题，只回滚 bbolt 提交，memory 仍为 03a/03b 的 L1 依赖。
- 若静态检查误报：修脚本（白名单/路径），不要禁用目标；必要时回滚脚本提交并重新评审规则。
- 若用户选择与推荐不同：按 §4 对应项调整设计/测试，不保留双份行为。
- 下游尚未接线；回滚不会破坏 app/cmd 或 02a 的接口。
