### 2.2 `internal/interfaces/clock.go`

```go
package interfaces

import "time"

// Clock is the only source of time for kernel and driver code.
// Business deadlines MUST be derived from this interface, never from
// context.WithTimeout or package-level time functions.
type Clock interface {
	Now() time.Time
	NewTicker(d time.Duration) Ticker
	NewTimer(d time.Duration) Timer
	Sleep(d time.Duration)
}

// Ticker mirrors time.Ticker. Stop does not close C and is idempotent.
// C has capacity 1; a slow receiver drops ticks, matching the standard library.
type Ticker interface {
	C() <-chan time.Time
	Stop()
}

// Timer mirrors the subset of time.Timer used by the kernel. Stop does not
// close C. The kernel never relies on Reset; each deadline creates a new
// Timer so a fake clock can advance deterministically.
type Timer interface {
	C() <-chan time.Time
	Stop()
}
```

- 为什么：ADR-0003 决策 5 的唯一时间入口。
- 谁实现：`internal/clock/realclock`（生产）、`internal/testutil/fakeclock`（测试）。
- 02a：两者均实现。
- 取舍：保持 ADR 字面形状，`Stop()` 不返回 bool，不提供 Reset；需要判断“是否已触发”时测试用具体 fake 的 `Fired()`，生产代码用非阻塞读 `C()`。

### 2.4 `internal/interfaces/driver.go`

```go
package interfaces

import (
	"context"
	"time"
)

type Driver interface {
	Name() string
	Open(ctx context.Context) error
	Close() error
	Capabilities() Capabilities
	Read(ctx context.Context, req ReadRequest) ([]Sample, Outcome)
	Write(ctx context.Context, req WriteRequest) (CommandHandle, error)
	Events() <-chan DriverEvent // nil for pull-only drivers
	Status() LinkStatus
}

type ReadRequest struct {
	Device   string
	Points   []string  // empty means all readable points for the device
	Deadline time.Time // zero means no per-call deadline; derived from Clock
}

type PointWrite struct {
	PointKey string
	Value    any
}

type WriteRequest struct {
	Device   string
	Writes   []PointWrite
	Deadline time.Time // zero means no per-call deadline; derived from Clock
}

type CommandHandle struct {
	Ref string // opaque driver-assigned correlation id, echoed in DriverEvent.Ref
}

type DriverEvent struct {
	Kind    EventKind
	Device  string
	Ref     string
	State   CommandState
	Sample  []Sample
	Payload []byte
	FPort   int // LoRa uplink port; 0 for non-LoRa events
	At      time.Time
}
```

- 为什么：ADR-0001 的三个扩展点之一；`FPort` 是给 `UplinkAdapter.DecodePayload` 的附加字段，属于 02a 冻结时的加法。

### 2.7 `internal/interfaces/store.go`

```go
package interfaces

import (
	"context"
	"time"
)

type RecordPhase string

const (
	PhaseAccepted RecordPhase = "accepted"
	PhaseFinal    RecordPhase = "final"
)

type AcceptedRecord struct {
	Device    string
	Seq       uint64
	ServiceID string
	At        time.Time
}

type FinalRecord struct {
	Device string
	Seq    uint64
	Code   int
	Msg    string
	Data   map[string]any
	At     time.Time
}

type Record struct {
	Device     string
	Seq        uint64
	ServiceID  string
	Phase      RecordPhase
	AcceptedAt time.Time
	FinalAt    time.Time
	Code       int
	Msg        string
	Data       map[string]any
}

type DeviceState struct {
	Device        string
	Online        bool
	LastSuccessAt time.Time
	LastSeq       uint64
	UpdatedAt     time.Time
}

type Store interface {
	BeginAccepted(ctx context.Context, rec AcceptedRecord) error
	Finish(ctx context.Context, rec FinalRecord) error
	Lookup(ctx context.Context, device string, seq uint64) (Record, bool, error)
	LastSeq(ctx context.Context, device string) (uint64, error)
	LoadDevices(ctx context.Context) ([]DeviceState, error)
	SaveDevices(ctx context.Context, states []DeviceState) error
	LoadSnapshot(ctx context.Context, device string) ([]Property, bool, error)
	SaveSnapshot(ctx context.Context, device string, props []Property) error
	DeleteExpired(ctx context.Context, before time.Time) (int, error)
	Close() error
}
```

冻结语义（写入接口注释，02b 契约测试逐条验证）：

- `BeginAccepted`：`(device,seq)` 已存在（accepted 或 final）返回 `ErrAlreadyAccepted`，不得覆盖。
- `Finish`：记录不存在返回 `ErrRecordNotFound`；已是 final 返回 `ErrAlreadyFinal`；成功后 phase=final。
- `Lookup`：不存在返回 `found=false, err=nil`。
- `LastSeq`：无记录返回 `0, nil`（`seq` 由云端从 1 起分配）。
- `LoadDevices`：空集合返回空切片与 nil。
- `SaveDevices`：按 device upsert，不删除未出现的 device。
- `LoadSnapshot`：不存在返回 `nil,false,nil`；存在时返回副本。
- `SaveSnapshot`：整设备快照原子替换。
- `DeleteExpired`：只删除 `phase=final && FinalAt.Before(before)` 的记录，accepted 永不自动删除（由 10 明确处理）；返回删除条数。
- 所有方法接受 ctx；实现必须在 ctx 取消时尽快返回。

## 3. 时钟设计

### 3.1 真实实现 `internal/clock/realclock`

```go
package realclock

import (
	"time"

	"github.com/dxinli/collect-code/internal/interfaces"
)

func New() interfaces.Clock { return clock{} }

type clock struct{}

func (clock) Now() time.Time { return time.Now() }
func (clock) NewTicker(d time.Duration) interfaces.Ticker {
	return &ticker{t: time.NewTicker(d)}
}
func (clock) NewTimer(d time.Duration) interfaces.Timer {
	return &timer{t: time.NewTimer(d)}
}
func (clock) Sleep(d time.Duration) { time.Sleep(d) }

type ticker struct{ t *time.Ticker }
func (t *ticker) C() <-chan time.Time { return t.t.C }
func (t *ticker) Stop()               { t.t.Stop() }

type timer struct{ t *time.Timer }
func (t *timer) C() <-chan time.Time { return t.t.C }
func (t *timer) Stop()               { t.t.Stop() }
```

- 只有该包可以出现 `time.Now/NewTicker/NewTimer/Sleep`。
- `NewTicker(d<=0)` 的 panic 由标准库给出，与 `time.NewTicker` 一致。
- `NewTimer(d<=0)` 由标准库立即到期。

### 3.2 FakeClock API `internal/testutil/fakeclock`

```go
package fakeclock

import (
	"sync"
	"time"

	"github.com/dxinli/collect-code/internal/interfaces"
)

type Clock struct { /* mu, now, seq, sleepers, timers, tickers, closed */ }

func New(start time.Time) *Clock
func (c *Clock) Now() time.Time
func (c *Clock) Advance(d time.Duration)
func (c *Clock) NewTicker(d time.Duration) interfaces.Ticker
func (c *Clock) NewTimer(d time.Duration) interfaces.Timer
func (c *Clock) Sleep(d time.Duration)

// Test helpers, not part of interfaces.Clock.
func (c *Clock) Close()         // idempotent; releases sleepers and stops all tickers/timers
func (c *Clock) NumSleepers() int
func (c *Clock) NumActive() int // active tickers + unfired timers + sleepers

type Ticker struct { /* ... */ }
func (t *Ticker) C() <-chan time.Time
func (t *Ticker) Stop()
func (t *Ticker) DroppedTicks() uint64 // test assertion

type Timer struct { /* ... */ }
func (t *Timer) C() <-chan time.Time
func (t *Timer) Stop()
func (t *Timer) Fired() bool
```

实现约束：

- 内部只用 `sync.Mutex` 保护状态；**不启动任何 goroutine**。`Sleep` 阻塞调用者，等待一个在 `Advance`/`Close` 时关闭的 channel。
- 所有事件按 `(deadline, 注册序号)` 排序；同 deadline 先注册先触发。触发每个事件时把 `now` 设为该事件 deadline，便于观测；`Advance` 返回后 `now = start+d`。
- Ticker 的 channel 容量 1；到期时非阻塞发送该次计划时刻；channel 满则丢弃并 `DroppedTicks++`。周期推进按 `next += period` 逐个计算，不累积用 `now+period`。
- Timer 的 channel 容量 1；一次性；`d<=0` 在创建时立即写入当前时刻并标记 fired。
- `Advance` 与 `Now/NewTicker/NewTimer/Sleep` 互斥；`Advance` 期间其他 goroutine 的注册会阻塞到 `Advance` 返回，并以最终 target 为当前时刻。因此测试必须**按周期逐步 Advance 并在每步等待组件静默**，不要一次 `Advance(24h)` 后期待组件正确地在中间时刻注册 timer。
- `Close` 后 `Sleep` 立即返回，`Advance` no-op，`NewTicker/NewTimer` 返回停止对象；确保清理不泄漏。

| `Sleep(10s)` | 阻塞；Advance(10s) 后返回，Now=target | `TestFakeClockSleepUnblocksOnAdvance` |
| `Sleep(0)` / 负值 | 立即返回，不注册 sleeper | `TestFakeClockSleepNonPositiveReturns` |
| `Close` 时 N 个 sleeper | 全部返回，`NumSleepers()==0` | `TestFakeClockCloseReleasesSleepers` |
| 100 个 Sleep goroutine + Close | goroutine 计数回到基线（有界轮询） | `TestFakeClockNoGoroutineLeakAfterClose` |
| Ticker 通道值 | 等于计划时刻，不是 Advance 的最终时刻 | `TestFakeClockTickerPeriodAndDrop` |

> 03a 的 24h/1440 tick 断言必须写成 1440 次 `Advance(period)`，每次用调度器的完成信号同步；不要一次 `Advance(24h)` 后期待 1440 个接收。此约束写入 FakeClock 包注释，避免 03a 误用。

## 4. 需要拍板的边界（A/B + 推荐）

### 4.1 真实 Clock 放哪个包

- **A（推荐）**：`internal/clock/realclock`。与 `internal/store/bbolt` 对称；`core` 只 import `interfaces.Clock`；静态检查禁止 core import realclock。
- **B**：`internal/interfaces/realclock`。接口与实现同包，省一个目录，但污染“纯契约”包，且容易让 core 顺手 import。
- **C**：`internal/core/clock/real`。直接违反“core 不得直接调用 time.*”的硬规则，静态检查会自我拒绝。

**推荐 A。代价**：新增一个目录与 import 路径；收益是规则可被静态检查机械执行。

### 4.2 最小内核组件选什么

- **A（推荐）**：`internal/core/engine` 生命周期组件。`New(clock, logger)` 用 `Clock.Now()` 记录 `StartedAt`；`Run(ctx)` 等待取消并用 `Clock.Now()` 计算 `Uptime`；在 `app.run` 中真实构造并记录 `started_at`。它不产生周期、不读设备、不计算相位，03a 后续把 scheduler 挂进来即可。
- **B**：`internal/core/clockprobe`，用 `NewTicker` 计数并发日志。能证明 ticker 接线，但属于测试假工作，会增加生产 goroutine 与噪声，且是“孤立实现”。
- **C**：提前实现 `internal/core/eventbus`。能自然用 Clock，但抢占 ticket 11 的范围。

**推荐 A。代价**：组件很小、只证明 `Now()` 接线；ticker/timer/sleep 的接线由 FakeClock 单元测试覆盖，03a 再在真实调度器上使用。

### 4.3 Ticker/Timer 的接口形状

- **A（推荐）**：ADR 字面 `C() <-chan time.Time; Stop()`，不提供 `Stop() bool`、`Reset`。真实实现用薄包装；fake 提供测试专用 `Fired()`/`DroppedTicks()`。
- **B**：`Stop() bool` + `Reset(d)`，贴近 `time.Timer`。真实包装更复杂；03a 目前只需要“新建 deadline timer”，不需要 Reset；`Stop` 结果可用 select 判断。

**推荐 A。代价**：无法直接知道 Stop 是否赶在触发前；用非阻塞读 channel 或具体 fake 的 `Fired()` 解决。

### 4.4 fake 实现放哪

- **A（推荐）**：`internal/testutil/fakeclock` 与 `internal/testutil/fake` 普通包，只被 `_test.go` import；`check-deps.sh` 禁止生产包 import `internal/testutil`。可跨多个包复用。
- **B**：各包 `_test.go` 内复制 fake。隔离好但重复严重，03a/03b/11 会各写一份。
- **C**：`internal/interfaces/fake`。接口包与实现耦合，且让契约包引入额外测试依赖。

**推荐 A。代价**：fake 是“生产目录中的测试工具”；用静态检查 + 包注释约束，不进入二进制（未被 cmd 引用）。

### 4.5 静态检查用 `go list -deps` 还是 grep

- **A（推荐，混合）**：
  - import 边界用 `go list -deps`：权威、传递闭包、尊重 build tag，能抓 core→drivers/store/bbolt 的间接依赖。
  - 禁止调用用 `grep`：匹配 `time.(Now|Since|Until|NewTicker|NewTimer|Tick|After|AfterFunc|Sleep)(` 与 `context.(WithTimeout|WithDeadline)(`；排除 `_test.go` 与整行注释。
- **B**：自写 `go/ast` 分析器。能处理 import alias、注释与字符串，但新增维护成本；当前仓库只有 shell 脚本检查的先例。
- **C**：只用 `go list`。只能查 import，查不到 `time.Now()` 调用，不满足验收。

**推荐 A。代价**：grep 对 `import t "time"` 别名与块注释有盲点；用包注释、评审与后续 AST 升级兜底。若将来出现误报/漏报，优先升级为 `go/ast`，不要加抑制清单。

### 4.6 Ticker 的投递/丢弃语义

- **A（推荐）**：channel 容量 1、非阻塞发送、满则丢弃并计数，忠实于 `time.Ticker`；测试按周期逐步 Advance 并在每步等待组件静默。03a 用 1440 次 Advance 验证 1440 tick。
- **B**：无缓冲阻塞发送，Advance 等消费者接收。能一次 Advance 投递全部 tick，但去掉“丢弃”语义，且无消费者时会死锁，不忠实标准库。

**推荐 A。代价**：03a 不能一次 `Advance(24h)` 后收 1440 tick；必须在测试中分步并同步。该约束已写入 FakeClock 文档与验收表。

### 4.7 `app.Run` 的注入方式

- **A（推荐）**：改为 `Run(ctx, Deps{Clock}, args, ...)`；`cmd/collect-code` 构造 `realclock.New()` 并传入，满足“装配只在 cmd”。
- **B**：`Run(ctx, args, ..., opts ...Option)` 保持旧调用；默认在 app 内构造真实时钟，违反装配规则，或所有旧测试都要显式传 Option。
- **C**：包级全局 Clock。违反“显式接收 Clock”，不可接受。

**推荐 A。代价**：仅改 `cmd/main.go` 与 `app_test.go` 的 `run` helper 两处调用；CLI 行为不变。

### 6.1 `scripts/check-time.sh`

```bash
#!/usr/bin/env bash
# Reject direct time and business-deadline calls in kernel and driver code.
set -u

roots=(internal/core internal/drivers)
pattern='\b(time\.(Now|Since|Until|NewTicker|NewTimer|Tick|After|AfterFunc|Sleep)|context\.(WithTimeout|WithDeadline))[[:space:]]*\('
hits=""
for root in "${roots[@]}"; do
	[ -d "$root" ] || continue
	out="$(grep -rnE --include='*.go' "$pattern" "$root" 2>/dev/null | grep -v '_test\.go:' || true)"
	# Ignore whole-line comments; block comments are a documented blind spot.
	out="$(printf '%s\n' "$out" | grep -vE ':[0-9]+:[[:space:]]*//' || true)"
	if [ -n "$out" ]; then hits="${hits}${out}"$'\n'; fi
done

if [ -n "$hits" ]; then
	echo "direct time/context-deadline calls are forbidden in core/drivers:" >&2
	printf '%s' "$hits" >&2
	exit 1
fi
echo "OK: no direct time or context deadline calls in core/drivers"
```

- 检查目录：`internal/core`、`internal/drivers`（后者尚不存在时跳过）。
- 禁止模式：`time.Now/Since/Until/NewTicker/NewTimer/Tick/After/AfterFunc/Sleep`、`context.WithTimeout/WithDeadline`。
- 排除 `_test.go`（测试可用真实超时保护自己）；排除整行 `//` 注释。
- 已知盲点：import alias、字符串字面量、块注释；由接口文档与评审兜底，后续可升级 AST。

### 6.2 `scripts/check-deps.sh`

```bash
#!/usr/bin/env bash
set -u
export GOFLAGS=
MODULE="github.com/dxinli/collect-code"

fail=0

check_root() {
	local root="$1" forbidden="$2"
	[ -d "$root" ] || return 0
	while IFS= read -r pkg; do
		[ -n "$pkg" ] || continue
		local deps hits
		deps="$(go list -f '{{range .Deps}}{{println .}}{{end}}' "$pkg" 2>/dev/null || true)"
		hits="$(printf '%s\n' "$deps" | grep -E "$forbidden" || true)"
		if [ -n "$hits" ]; then
			echo "FAIL: $pkg imports forbidden packages:" >&2
			printf '%s\n' "$hits" >&2
			fail=1
		fi
	done < <(go list "./$root/..." 2>/dev/null || true)
}

common="${MODULE}/internal/(drivers|channels|adapters|store|testutil|clock/realclock)(/|$)|^go\\.etcd\\.io/bbolt(/|$)"
core="${common}|${MODULE}/internal/core(/|$)"
check_root internal/core "$core"
check_root internal/drivers "${common}"

# interfaces must stay a pure contract: no imports from this module.
check_root internal/interfaces "${MODULE}/"

if [ "$fail" -ne 0 ]; then exit 1; fi
echo "OK: kernel import boundaries hold"
```

- `internal/core` 禁止：具体 drivers/channels/adapters/store（含 bbolt/memory）、bbolt、realclock、testutil；core 子包互相 import 允许。
- `internal/drivers` 禁止：channels/adapters/store、bbolt、realclock、testutil、core。
- `internal/interfaces` 禁止任何本模块 import。
- 使用 `.Deps` 传递闭包，能抓间接 import；build tag 由 go list 处理。
- 不使用网络；只分析本地包。

## 10. 风险与回滚

| 风险 | 影响 | 缓解 |
|---|---|---|
| 接口过早冻结，04b/09 需要新字段 | 返工 | 只做加法；调用方使用带字段名的 composite literal；方法签名变化必须停下重评审 |
| `Data map[string]any` 经 JSON 往返后数字类型变化 | 02b/10 回放比较失败 | 02b 用 JSON 语义比较；若需精确 Go 类型，评估 `json.RawMessage` 并重评审 |
| FakeClock 一次 Advance 多周期导致 tick 丢弃 | 03a 的 1440 tick 断言失败 | 文档强制“分步 Advance + 每步同步”；`DroppedTicks()` 可断言丢弃 |
| `Advance` 持锁，消费者在 tick 内注册 timer 会等到 target | 组件看到错误当前时间 | 禁止多周期跳跃；按周期步进并等待静默 |
| grep 静态检查漏掉 import alias | 规则被绕过 | interfaces 文档 + 评审；后续升级 go/ast；CI 仍能抓绝大多数直接调用 |
| `go list` 在 drivers 目录尚不存在时报错 | 检查失败 | 脚本先判目录，再 `go list ... || true`；`go build` 仍负责真实编译错误 |
| 改 `app.Run` 签名 | 既有测试/调用点失败 | 只有 `cmd/main.go` 与 `app_test.go` 的 helper 两处；编译器强制发现 |
| engine 增加 startup 字段影响日志断言 | 既有测试失败 | 不删除既有字段；只新增 `started_at`，既有断言均为子串匹配 |
| realclock 被 core 误 import | 违反时间规则 | `check-deps.sh` 显式禁止 core import realclock |
| 无外部 goleak，泄漏检测不全面 | 漏掉组件 goroutine | 组件用 done/WaitGroup 精确断言；FakeClock 自身不启动 goroutine |

**回滚策略**：

- 每个 commit 独立可回滚；尚未有下游 ticket 依赖，回滚接口提交不会破坏其它模块。
- 若 FakeClock 语义有误：只回滚 fakeclock 提交，生产 realclock 不受影响；修正后重跑 03a 前置测试。
- 若静态检查误报阻塞 CI：修正脚本（过滤/规则），不要禁用目标；必要时回滚脚本提交并重新评审规则。
- 若 app 接线导致测试不稳定：回滚 app 提交，保留 engine 单测，重新设计注入方式后再提交；不得跳过验收项 3。
- 若用户要求调整接口形状：按 CLAUDE.md 停止实现，回到计划评审。
