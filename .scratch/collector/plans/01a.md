## 1. 模块与目录

### 1.1 Go module path 与二进制名

- **module path**：`github.com/dxinli/collect-code`。若远端组织不同，**第一次提交前**替换；之后改成本扩散到全仓。
- **二进制名**：`collect-code`。
- `go.mod`：`go 1.27` + `toolchain go1.27.4`（最低要求与构建工具链分离，避免 1.27.0–1.27.3 环境失败）；唯一第三方依赖 `gopkg.in/yaml.v3 v3.0.1`；提交 `go.sum`。

### 1.2 目录布局

## 2. 配置解析

### 2.1 类型模型

- `config.yaml` → `Config{Node,Northbound,Adapter,Timing,Cache,Queue,State,Log,Health}`
- `links.yaml` → `LinksFile{Links []Link}`
- `devices.yaml` → `DevicesFile{Devices []Device}`
- `profiles/*.yaml` → `Profile{profile,device_type,poll_interval_s,points,services,events,payload?}`
- `Bundle{Config,Links,Devices,Profiles map[string]*Profile, ProfileSources map[string]string}`
- **`adapter.topics` 用 5 字段固定 struct**，不用 `map[string]string`；`log.redact_fields` 是唯一有意的开放 `[]string`。
- **零值合法字段用指针/存在标志**（01a 不校验范围，但类型现在定对）：`min/max`、`modbus.address`、`address.unit_id`（0 是广播地址）、`stale_after_s`、`read_deadline_ms`、`timeout_ms`、`retry_max`、`f_port`、`port`。否则 01b 无法区分「缺失」与「0」。
- **同名 profile 跨文件**：视为结构性错误（列出两个文件名），不做静默覆盖。
- LoRa `chirpstack` 块**不写自定义 UnmarshalYAML**，保留导出 `APITokenEnv string`；decode 完成后在 `resolveSecrets` 阶段转成未导出 `apiToken Secret`。只有 `Secret` 自己是标量 Unmarshaler。

### 2.2 默认值与 null 语义

- `config.Default() Config` 每次返回**新分配**的 slice/pointer，禁止返回包级可变变量（yaml 会整体替换 slice、合并 map，复用会污染默认值）。
- 先 `v := Default()`，再 `decoder.Decode(&v)`；利用字段级覆盖。
- 明确 null：
  - `log: null` / `timing: null` 会把整块 struct 清零（yaml.v3 行为），**不当作默认值**；文档与测试固定此语义。
  - `password: null` 不调用 UnmarshalYAML，视为未配置。
  - `redact_fields: []` 显式关闭键名脱敏（值兜底仍生效）；`null` 清空默认。两者测试。
- 不预填任何 map 到 `Config`。
- 01a 不展开 `{node.id}` 等模板。

### 2.3 严格解析流程

统一 helper，返回结构化 `Diagnostic{File,Line,RuleID,Message}`（01a 的 `RuleID` 为空；01b 填 V01…）：

1. 读取 bytes；用第一个 decoder 解到 `yaml.Node`：
   - `io.EOF` 或 `node == nil` → `empty document`；
   - `node.Kind == DocumentNode` 但内容为 null/空 → `empty document`。
2. 用**新的** decoder（`KnownFields(true)`）解到目标 struct（不要用 `node.Decode`，会丢失 KnownFields）。
3. 再 `Decode(&extra)` 必须 `io.EOF`，否则 `multiple YAML documents not supported`。
4. 错误包装文件名与行号；**规范化 yaml.TypeError**：删除反引号内的标量原文，只保留 `line N: cannot unmarshal <tag> into <type>`，防止凭据值回显。
5. `profiles/` 用 `os.ReadDir` + 后缀过滤（`.yaml`/`.yml`）+ 文件名排序；非 YAML 忽略（不用 Glob，避免 `[`/`*` 注入且 `.yml` 匹配不到）。
6. 文件存在性：config/links/devices 必须存在，profiles 目录必须存在；列表允许为空。
7. yaml.v3 自带重复键拒绝，可测但不升级为业务规则。

### 2.4 01a 的「必填」边界

只做字段存在/非空，**不做**语义规则：

| 对象 | 01a 检查 |
|---|---|
| node | `id`、`product_key` 非空 |
| northbound.mqtt | `broker` 非空 |
| 每条 link | `id`、`driver` 非空；serial/tcp/chirpstack 至少一块存在（**仅存在性，不校验 driver↔块匹配**） |
| 每个 device | `sn`、`device_type`、`profile`、`link` 非空；`address` 存在（`*Address != nil`，`unit_id: 0` 合法） |
| 每个 profile | `profile` 名非空 |

- 错误格式 `file: field.path: required`；聚合顺序 config → links → devices → profiles（按文件名排序）。
- 跨文件缺少必填一次性输出；语法/未知键按首错返回。

### 2.5 env 凭据

- `Secret` 类型（值接收者实现 `String/GoString/MarshalJSON`，避免指针接收者被绕过）：
  - 标量 `UnmarshalYAML`；`env:NAME` 记引用，普通字符串记字面量；mapping/sequence 报通用错误，**不回显节点内容**。
  - 未导出 `value/source/envName`；`Masked()` → `[set]/[set via env VAR]/[unset]`；`Reveal()` 显式取值，01a 无调用方。
- `Load(dir, WithEnv(lookup))`，默认 `os.LookupEnv`，测试注入。
- 解析 `mqtt.password` 与 LoRa `chirpstack.api_token_env`：
  - `env:` 后变量名须匹配 `[A-Za-z_][A-Za-z0-9_]*`；非法名报错时**不回显原名**（防止把字面量 token 写进变量名位）。
  - 引用缺失 → `links.yaml: link lora-gw: api_token_env CHIRPSTACK_TOKEN is not set`。
  - 变量存在但为空 / 字面量空串 / `null` → 视为未配置（`[unset]`），不报错；`api_token_env` 为空同理。
  - `api_token_env` 的值是**变量名**，不写 `env:` 前缀；写 `env:FOO` 会按该字面名查找而失败，文档写明。
  - `env:` 前缀大小写敏感；`env: NAME` 带空格视为非法名并报错（不回显）。

### 2.6 与 01b 的边界

| 01a 做 | 01b 做 |
|---|---|
| YAML 语法、未知键、类型错、多文档、空文档 | V01… 规则编号与 `file:line:col: rule_id` 诊断 |
| 必填字段非空、env 引用可解析 | 引用完整性（profile/link 存在） |
| 默认值合并、null 语义 | 唯一性（link id/device sn/point key/service_id/event_id） |
| 文件/目录存在性 | 数值范围（min≤max、scale>0、周期≥1、qos∈{0,1}） |
| 凭据脱敏基础设施 | 枚举、driver↔传输块互斥、只读点写入、端口冲突 |
| **最小** config-check 输出 | golden corpus、完整摘要、行列级定位 |

**明确**：`driver: modbus-rtu` 必须配 serial、`driver: lorawan` 必须配 chirpstack 等互斥规则一律归 01b；01a 只检查「至少一个传输块存在」。实现者不得写半成品规则。

## 3. 日志契约

### 3.1 选型与选项

- 标准库 `log/slog` + `slog.NewJSONHandler`。
- `logging.Options{Level slog.Level; Format string; Output io.Writer; RedactFields []string; RedactValues []string}`；`Output` 默认 stderr；`RedactValues` 由 `app` 从所有已解析 Secret 收集。
- `logging.ParseOptions(cfg) (Options, error)` 作为**共享校验**，`config-check` 与 `run` 都调用：level 枚举、format 仅 `json`、空值处理。`log: null` 走默认。
- 不用包装 Handler，改用 **`slog.HandlerOptions.ReplaceAttr`**：它在值已 resolve 后调用，天然避开 `LogValuer` 明文泄漏；`WithAttrs/WithGroup` 由标准库管理，无需自写递归。
- `record.Message` 单独处理：在 `ReplaceAttr` 之外用一个薄包装 `sanitizeMessage` 对 `r.Message` 替换已注册 secret 子串（Clone 后修改），并约定 message 不放动态值。

### 3.2 固定字段

- `internal/logging/fields.go` 常量 `device/point/seq/link/reason`。
- `Fields{Device,Point,Link,Reason string; Seq *uint64}`；`Seq` 用指针，**0 是合法序号**，避免被当空省略。`Attrs()` 只输出非 nil/非空。
- 五个是保留上下文键，非每行必现；测试用 Fields 生成全键记录，断言键名与类型（`json.Decoder.UseNumber` 或 struct `uint64`，避免 float64）。
- 基线键 `time/level/msg/component/event` 允许。

### 3.3 脱敏实现（ReplaceAttr + 值兜底）

- 键名归一化小写；等于 `RedactFields` 项或以 `_<name>`/`.<name>` 结尾 → `[REDACTED]`。
- 值兜底（不依赖配置，用户删默认列表也生效）：
  - `KindString` 与已注册 secret 精确相等 → `[REDACTED]`；
  - `KindAny` 的 `error`/`Stringer`/`fmt.Stringer` 取字符串比较；
  - 字符串里含 `://user:pass@` 的 URL → 用 `net/url` 把 userinfo 替换为 `[REDACTED]`（解析失败则整值替换，不打印原串）；
  - message 子串替换（见 3.1）。
- `Secret` 的 `%v/%+v/%s/json.Marshal` 均不出现明文。
- 摘要用显式 DTO；密码/token 只显示状态；broker 用 `url.Parse` 去 userinfo，解析失败显示 `[unparseable broker]`。
- 解析期错误（logger 初始化前）写 stderr：只含文件名/字段路径/变量名；yaml TypeError 已规范化。
- CI grep：`internal/` 与 `cmd/` 禁止直接 `fmt.Print*`/`log.Print*`（CLI stdout allowlist）。

## 4. 子命令

### 4.1 契约

- `app.Run(ctx context.Context, args []string, stdout, stderr io.Writer, lookupEnv func(string)(string,bool)) int`；`main` 只传 `os.Args[1:]`、`os.Stdout/Stderr`、`os.LookupEnv`。避免测试改全局变量。
- 标准库 `flag`，每命令独立 `FlagSet(ContinueOnError)`，`SetOutput(stderr)`；`flag.ErrHelp` → 0。
- 退出码常量 `ExitOK=0/ExitError=1/ExitUsage=2`：
  - 无子命令、未知子命令、未知 flag、`--config` 缺值/空值、多余位置参数 → 2；
  - 配置/运行错误 → 1；
  - `-h`/`--help` → 0。
- `--config` 默认 `/etc/collect-code`（三个命令一致）；`config-check` 摘要写 stdout，错误写 stderr；`run` 日志只写 stderr。
- `version` 固定 `key: value` 行序：binary、version、commit、build_date、go、platform（GOOS/GOARCH）。

### 4.2 config-check（01a 最小输出）

- 加载 → 严格解析 → 必填 → env 解析 → 共享日志选项校验。
- 成功只输出一行：`config ok: node=<id> product_key=<key> links=<N> devices=<N> profiles=<N>`（`lookupEnv` 注入后不出现明文）。
- 失败：结构化 Diagnostic 渲染为 `file:line: message`，退 1。
- **完整摘要归 01b**；01a 不做 golden 摘要。

### 4.3 run

- **先装信号 handler，再记 startup**：

  ```go
  sigCh := make(chan os.Signal, 1)
  signal.Notify(sigCh, syscall.SIGINT, syscall.SIGTERM)
  defer signal.Stop(sigCh)
  signal.Ignore(syscall.SIGHUP)   // 17a 之前误发 SIGHUP 不应杀进程
  ```
- 加载失败 → stderr 退 1。
- 初始化 JSON logger；startup 记录 node/version/links/devices 计数。
- 记录 warn `msg="skeleton mode: no drivers or channels wired"`、`reason="skeleton"`。
- 用独立 goroutine 读 `sigCh`，记 `event=shutdown`、`reason=signal`、`signal=terminated|interrupt`，然后 `cancel()`。
- `runEngine(ctx,cfg,logger)` 只做 `<-ctx.Done(); return nil`；`app.Run` 把 `context.Canceled` 映射为 0，其他错误为 1。
- `defer cancel()`；第二次信号在 `signal.Stop` 后恢复默认动作。
- **不创建 state.db、不 bind 8080/1700/9100、不连 MQTT、不伪造 tick**。

## 5. 构建

### 5.1 Makefile

| 目标 | 作用 |
|---|---|
| build | 本机 build 到 `dist/collect-code` |
| build-linux-amd64 / arm64 | `CGO_ENABLED=0 GOOS=linux GOARCH=... go build -trimpath -buildvcs=false -buildmode=exe` |
| build-all | 两者 |
| verify-static | `scripts/verify-static.sh dist/collect-code-linux-amd64 amd64` 与 arm64 |
| test / test-race | `go test ./...`；race 显式 `CGO_ENABLED=1` |
| vet / fmt-check | `go vet ./...`；`gofmt -l` 为空 |
| check | fmt-check vet test build-all verify-static + `config-check configs/example` |
| clean | 删 dist/ |

- 产物名写死为 `dist/collect-code-linux-amd64`、`dist/collect-code-linux-arm64`。
- 构建前显式 `GOFLAGS=`，防止环境注入 `-buildmode=pie`。

### 5.2 ldflags

- `VERSION/COMMIT/BUILD_DATE` 由 `git describe`/`rev-parse`/`date` 注入；非 git 回退 `dev/none`。
- `-s -w -trimpath -buildvcs=false`（与 `git describe` 不冲突：后者是 shell 层取版本）。
- 支持 `SOURCE_DATE_EPOCH` 派生 BUILD_DATE。

### 5.3 静态断言（`scripts/verify-static.sh`）

- `LC_ALL=C`；参数：二进制 + 期望架构。
- 主判据：`go version -m` 的 `GOOS=linux`、`GOARCH=<期望>`、`CGO_ENABLED=0`。
- 补充：`file` 含 `ELF 64-bit` 且架构匹配；`readelf -l` 无 INTERP（无 readelf 时 `ldd` 报 not a dynamic executable；`ldd` 的 `not executable` 不放行）。
- 只读产物，不执行交叉架构二进制。

## 8. 风险与取舍

1. **越过边界做 01b 校验**：§2.6 为 checklist；字段存在与规则校验分成两个函数边界；测试命名区分 TestParse/TestRequired 与未来 TestRule；互斥规则只在 01b。
2. **日志脱敏漏路径**：ReplaceAttr（值已 resolve）+ Secret 值接收者屏蔽 + 摘要 DTO + message 子串替换 + sentinel 扫描（含解析失败路径）+ CI 禁直出。
3. **静态构建断言脆弱**：只断言属性，不断言哈希；`go version -m` 主判据；`LC_ALL=C`；`-buildmode=exe`；固定 GOFLAGS。
4. **严格未知键盲区**：显式 struct；禁 inline；不给容器写 UnmarshalYAML；仅 redact_fields 开放；二次 Decode 必须 EOF。
5. **run 骨架被误解**：startup 后立刻 warn skeleton；不模拟 tick/端口/状态库；信号先装后 startup；runEngine 返回 nil。
6. **yaml TypeError 回显**：规范化错误文本；凭据字段 mapping + sentinel 用例。
7. **stdlib flag 的 UX 限制**：独立 FlagSet + 统一 usage、退出码表；queue flush 二级分发；子命令树膨胀再评估 cobra。

## 9. 明确不做

- 不实现 Driver/Channel/UplinkAdapter/DownlinkAdapter/Clock/Store 任何接口或假实现；不建 `internal/interfaces`。
- 不实现 scheduler/state/invoker/forward/eventbus/queue 治理/新鲜度/离线判定。
- 不做 01b 校验：V 规则号、file:line:col、引用完整性、唯一性、数值范围、枚举、driver↔传输块互斥、只读点写入、端口冲突、golden corpus、完整摘要。
- 不做 SIGHUP 热重载、config_rejected。
- 不接 Modbus/RTU/TCP/MQTT/ChirpStack；不做 simulate/snapshot/queue flush。
