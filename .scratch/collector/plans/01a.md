> 范围仅限 `.scratch/collector/issues/01a-skeleton.md` 的 5 条验收项。本计划不写代码。

## 1. 模块与目录

### 1.1 Go module path 与二进制名

- **module path**：`github.com/dxinli/collect-code`。理由：git `user.name` 是 `dxinli`；带点符合模块路径惯例；未来推远端不需重命名。若远端组织不同，**第一次提交前**替换 `go.mod` 与全仓 import。
- **二进制名**：`collect-code`，与仓库名、`/etc/collect-code` 一致。
- `go.mod`：`go 1.27.4`（本机版本）；唯一第三方依赖 `gopkg.in/yaml.v3 v3.0.1`；提交 `go.sum`。

### 1.2 目录布局

```
cmd/collect-code/main.go     # 仅组装 Deps、调用 app.Run、os.Exit
internal/app/                # 子命令分发、config-check、run 生命周期
internal/config/             # 四层 YAML 类型、默认值、严格解析、Secret、摘要
internal/logging/            # slog JSON、固定字段、脱敏 Handler
internal/version/            # Version/Commit/BuildDate，ldflags 注入
configs/example/             # 可直接运行的示例四层配置
scripts/verify-static.sh
internal/config/testdata/
Makefile
go.mod / go.sum
```

- **01a 不创建** `internal/interfaces`、`internal/core`、`drivers`、`channels`、`adapters`、`store` 的任何空包/空接口/占位文件。
- 依赖方向：`cmd → internal/app → {config, logging, version}`；`config` 与 `logging` 互不依赖，由 `app` 映射 `config.Log → logging.Options`，避免循环。
- 装配约束（ADR-0001）：具体实现只在 `cmd` 构造；`internal/app` 只持有接口/工厂。

## 2. 配置解析

### 2.1 类型模型

- `config.yaml` → `Config{Node,Northbound,Adapter,Timing,Cache,Queue,State,Log,Health}`
- `links.yaml` → `LinksFile{Links []Link}`
- `devices.yaml` → `DevicesFile{Devices []Device}`
- `profiles/*.yaml` → `Profile{profile,device_type,poll_interval_s,points,services,events,payload?}`
- 聚合 `Bundle{Config,Links,Devices,Profiles map[string]*Profile}`（重复问题留 01b）
- **关键**：`adapter.topics` 建成 5 个固定字段的 struct，**不用 `map[string]string`**，否则拼错的 topic 名会被当成合法扩展键，违背未知键报错。`log.redact_fields` 是唯一有意的开放 `[]string`。
- LoRa `api_token_env` 保持环境变量名字符串；解析后得到内部 `Secret`，不放进可导出字段。

### 2.2 默认值

- `config.Default()` 按 Spec §1 给出全部默认：qos=1、keepalive=60、TLS 关闭、reconnect、全部 timing、cache、`queue.pending_max=4`、state、log、redact_fields 四项、health disabled/127.0.0.1:9100、adapter.name 与五个 topic 模板。
- 解析方式：`v := Default()` → `decoder.Decode(&v)`，利用 yaml.v3 字段级覆盖。**不得**先解零值再逐字段补默认（丢失 map 部分覆盖语义）。
- 01a 不展开 `{node.id}` 等模板；摘要按原样显示。

### 2.3 严格解析流程

每个文件统一 helper：
1. `os.Open`，错误包装为 `config.yaml: open: ...`（不打印内容）。
2. `yaml.NewDecoder` + `KnownFields(true)`，解到目标类型；未知键/类型错带行号。
3. 再 `Decode(&extra)` 必须 `io.EOF`，否则报 `multiple YAML documents not supported`。
4. 空文件/空文档报 `empty document`。
5. 错误包文件名；01a 格式 `file:line: message`；**01b 才升级为 `file:line:col: rule_id: message`**。
6. `profiles/` 用 `filepath.Glob("*.yaml")`（兼容 `*.yml`），排序后加载；忽略非 YAML。
7. 文件存在性：config/links/devices 必须存在，profiles 目录必须存在；列表允许为空（「至少一个设备/链路」不是 01a 规则）。
8. yaml.v3 自带重复键拒绝，可测但不升级为业务规则。

### 2.4 01a 的「必填」边界

只做字段存在/非空，不做语义规则：

| 对象 | 01a 检查 |
|---|---|
| node | `id`、`product_key` 非空 |
| northbound.mqtt | `broker` 非空 |
| 每条 link | `id`、`driver` 非空；serial/tcp/chirpstack 至少一块存在 |
| 每个 device | `sn`、`device_type`、`profile`、`link`、`address` 非空 |
| 每个 profile | `profile` 名非空 |

跨文件收集「缺失必填」后一次输出；未知键/语法错按 yaml 首错返回（01b 再做完整诊断）。

### 2.5 env 凭据

- `Secret` 类型：
  - 自定义 `UnmarshalYAML` 接受标量；`env:NAME` 记引用，普通字符串记字面量；mapping/sequence 报通用错误，不回显节点内容。
  - 内部字段不导出：`value/source/envName`。
  - `String/GoString` → `[REDACTED]`；`MarshalJSON` → `"[REDACTED]"`；`Masked()` → `[set]/[set via env VAR]/[unset]`。
  - `Reveal()` 显式命名，只有未来的 MQTT/ChirpStack 客户端可调；01a 无调用方。
- `Load(dir, WithEnv(lookup))`，默认 `os.LookupEnv`，测试注入 map 或 `t.Setenv`。
- 解析 `mqtt.password` 与 LoRa `chirpstack.api_token_env`：
  - 引用缺失 → `links.yaml: link lora-gw: api_token_env CHIRPSTACK_TOKEN is not set`（只出现变量名）。
  - `env:` 空名报错；`api_token_env` 为空视为未配置。
- 不实现任意字段 env 覆盖；只有上述凭据入口。
- 字面量以 `env:` 开头会被当引用，文档写明，01a 不提供转义前缀。

### 2.6 与 01b 的边界

| 01a 做 | 01b 做 |
|---|---|
| YAML 语法、未知键、类型错、多文档、空文件 | V01… 规则编号与统一诊断格式 |
| 必填字段非空、env 引用可解析 | 引用完整性（profile/link 存在） |
| 默认值合并 | 唯一性（link id/device sn/point key/service_id/event_id） |
| 文件/目录存在性 | 数值范围（min≤max、scale>0、周期≥1、qos∈{0,1}） |
| 凭据脱敏基础设施 | 枚举、driver↔传输块互斥、只读点写入、端口冲突 |
| 简单摘要 | golden corpus、行列级定位、摘要细化 |

实现者若想写 min>max、profile 找不到等检查，一律推迟到 01b，代码不留半成品规则。

## 3. 日志契约

### 3.1 选型

- 标准库 `log/slog` + `slog.NewJSONHandler`，不引第三方日志库。
- `logging.Options{Level,Format,RedactFields}`；`app` 从 `config.Log` 映射。01a 只支持 `format=json`，其他值启动报 `unsupported log.format (only json in v0.1)`。
- 输出 stderr；01a 不做文件轮转。构造后显式传递，不依赖全局 logger。

### 3.2 固定字段

- `internal/logging/fields.go` 定义常量 `device/point/seq/link/reason`，类型 string/string/uint64/string/string。
- `Fields{...}.Attrs()` 只输出非空字段；禁止别名 `device_sn/link_id`。
- 五个是**保留上下文键**，非每行必现；测试用 `Fields` 生成全键记录，断言键名与类型。
- 基线键 `time/level/msg/component/event` 允许；测试断言保留键拼写正确。

### 3.3 redact_fields 实现

- Handler 层 `redactingHandler` 包装 `slog.Handler`，覆盖 Enabled/Handle/WithAttrs/WithGroup；递归处理 group 与预存 attrs。
- 键名归一化小写；等于配置项或以 `_<name>`/`.<name>` 结尾则脱敏（覆盖 `mqtt_password`、`api_token`），值替换 `[REDACTED]`。
- 值兜底：注册所有已解析 Secret 的明文（及 broker URL 的 userinfo 密码），任何 attr 值精确相等即替换，即使键名不在列表。
- 不解析任意 `LogValuer`（避免把 secret 暴露给不可信代码）。
- Secret 自身 String/GoString/MarshalJSON 全屏蔽。
- 摘要用显式 DTO：密码/token 只显示 `[set]`；broker URL 用 `net/url` 去 userinfo；绝不 dump 原始 YAML/Bundle。
- 解析期错误（logger 初始化前）只写字段路径/文件名/env 变量名，不拼值/内容；Secret.UnmarshalYAML 错误不带标量原文。
- CI grep：禁止 `internal/` 与 `cmd/` 中直接 `fmt.Print*`/`log.Print*`（CLI stdout allowlist）。
- redact_fields 来自配置可改，但值兜底不依赖配置。

## 4. 子命令

### 4.1 选型：标准库 flag

- `flag.NewFlagSet(name, ContinueOnError)`，各命令独立 FlagSet，`SetOutput(stderr)`。
- 理由：三个平级命令，无复杂嵌套；少依赖。未来 `queue flush` 用二级分发；变复杂再评估 cobra。
- 退出码：0 成功；1 配置/运行错；2 用法错。`main` 只 `os.Exit(app.Run(...))`。

### 4.2 version

不读配置、不初始化日志；stdout 输出二进制名、Version、Commit、BuildDate、runtime.Version()、GOOS/GOARCH。变量在 `internal/version`，默认 `dev/none/unknown`。

### 4.3 config-check --config <dir>（默认 /etc/collect-code）

加载 → 严格解析 → 必填 → env 解析 → 打印摘要；错误写 stderr 退 1。摘要含：
- node.id/product_key；
- MQTT scheme/host/port（去 userinfo）、client_id 模板、username、password 状态、qos、TLS；
- adapter 名与 topic 模板；
- timing 关键值；
- links id/driver/端点（不显示 token）；
- profiles 文件名/名、point/service/event 数量；
- devices sn/type/profile/link/address；
- log level/format/redact_fields；
- health、state.db_path。

### 4.4 run --config <dir>

- 加载失败 → stderr 报错退 1。
- 初始化 JSON logger，记录 startup（component=app、node、version、links/devices 计数）。
- 记录 warn `msg="skeleton mode: no drivers or channels wired"`、`reason="skeleton"`，避免误认为采集已运行。
- `signal.NotifyContext(SIGINT,SIGTERM)`；`<-ctx.Done()` 后记 `event=shutdown`、`reason=signal`、`signal=terminated|interrupt`，返回 0。
- 不创建 state.db、不 bind 8080/1700/9100、不连 MQTT、不伪造 tick。
- `runEngine(ctx,cfg,logger)` 接收 ctx，未来组件继承取消；CLI 只做信号接线。

## 5. 构建

### 5.1 Makefile

| 目标 | 作用 |
|---|---|
| build | 本机 build 到 dist/collect-code |
| build-linux-amd64 / arm64 | CGO_ENABLED=0 GOOS=linux GOARCH=... |
| build-all | 两者 |
| verify-static | 跑 scripts/verify-static.sh |
| test / test-race | go test；race 需 CGO，只用于测试作业 |
| vet / fmt-check | go vet；gofmt -l 为空 |
| check | fmt-check vet test build-all verify-static |
| clean | 删 dist/ |

### 5.2 ldflags

```
VERSION ?= $(shell git describe --tags --always --dirty 2>/dev/null || echo dev)
COMMIT ?= $(shell git rev-parse --short HEAD 2>/dev/null || echo none)
BUILD_DATE ?= $(shell date -u +%Y-%m-%dT%H:%M:%SZ)
LDFLAGS := -s -w -X .../internal/version.Version=$(VERSION) -X ...Commit=$(COMMIT) -X ...BuildDate=$(BUILD_DATE)
```

加 `-trimpath -buildvcs=false`；支持 SOURCE_DATE_EPOCH；否则承认构建时间不可复现。

### 5.3 静态与架构断言（scripts/verify-static.sh）

参数：二进制 + 期望架构。逐项断言：
1. `file` 含 `ELF 64-bit`；
2. 架构匹配 x86-64 / aarch64|ARM64；
3. 静态：`readelf -l` 无 INTERP；无 readelf 时 `ldd` 报 not a dynamic executable；不只看 file 的 statically linked（static-pie 也合法）；
4. `go version -m` 断言 GOARCH=期望 且 CGO_ENABLED=0（最强判据）；
5. 可选 GOOS=linux；
6. 只读产物，不执行交叉架构。

## 8. 风险与取舍

1. **越过边界做 01b 校验**：以 §2.6 为 review checklist；「字段存在」与「规则校验」分成两个函数边界，后者不实现；TODO 指向 01b；测试命名区分 TestParse/TestRequired 与未来 TestRule。
2. **日志脱敏漏路径**：Handler 层 + Secret 自带屏蔽 + 摘要 DTO 三重防线；secret 值注册；sentinel 扫 stdout+stderr；CI 禁直出。
3. **静态构建断言脆弱**：只断言属性（ELF/架构/无 INTERP/CGO=0/GOARCH），不断言哈希；以 `go version -m` 为主判据；readelf 优先、ldd 回退；固定工具链；支持 SOURCE_DATE_EPOCH。
4. **严格未知键盲区**：已知结构用显式 struct；禁 inline；仅 redact_fields 开放；强制第二次 Decode 为 EOF。
5. **run 骨架被误解**：启动 warn 明示 skeleton；不模拟 tick/端口/状态库；信号测试进 CI；runEngine 显式接收 ctx。
6. **stdlib flag 的 UX 限制**：每命令独立 FlagSet + 统一 usage、退出码表；queue flush 二级分发；子命令树膨胀再评估 cobra。

## 9. 明确不做

- 不实现 Driver/Channel/UplinkAdapter/DownlinkAdapter/Clock/Store 任何接口或假实现；不建 `internal/interfaces`（02a 负责）。
- 不实现 scheduler/state/invoker/forward/eventbus/queue 治理/新鲜度/离线判定。
- 不做 01b 校验：V 规则号、file:line:col、引用完整性、唯一性、数值范围、枚举、driver↔传输块、只读点写入、端口冲突、golden corpus。
- 不做 SIGHUP 热重载、config_rejected。
- 不接 Modbus/RTU/TCP/MQTT/ChirpStack；不做 simulate/snapshot/queue flush。
- 不引 bbolt、不建 state.db、不做健康端点。
- 不做 MQTT 连接/重连/TLS；不展开模板；不做报文编解码/irrigation-v1。
- 不引 cgo、Web UI、外部数据库、第三方 CLI/日志框架；除 yaml.v3 不新增依赖。
- 不把硬件数值写成代码常量；ASSUMED 只在台账与配置/夹具。
- 不做发布文档包（19a/19b）。
