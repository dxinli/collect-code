## 2. 已核实的现状与材料差异

### 2.1 接口（冻结，不得改签名）

- `interfaces.Channel`：`Publish(ctx, Message) error`、`Subscribe(ctx, filter) (Subscription, error)`、`Status() ChannelStatus`、`Close() error`。
- `Message`：`Topic string`、`Payload []byte`、`QoS QoS`、`Retain bool`、`DedupKey string`。
- `QoS` 只有 `QoS0`、`QoS1`；没有 QoS2。
- `ChannelStatus`：`Connected bool`、`LastError string`、`ChangedAt time.Time`。
- `Subscription`：`C() <-chan Message`、`Close() error`。
- 冻结注释明确：通道不可用时 `Publish` 必须返回 `ErrNotConnected` 或 `ErrClosed`，并用 `%w` 包装，调用方用 `errors.Is` 分类。
- `errors.go` 有 `ErrNotConnected`、`ErrClosed`、`ErrUnsupported`；05a 使用它们，不新增跨 seam 哨兵。
- `interfaces.Clock`：`Now`、`NewTicker`、`NewTimer`、`Sleep`；`Timer` 不依赖 `Reset`。

构造期校验（返回 plain error，不启动 goroutine）：

- `Clock != nil`；`BrokerURL` 非空、可解析、scheme 受支持、host 非空；
- `ClientIDTemplate` 渲染后非空、UTF-8、无控制字符、长度 ≤ 65535；

- broker URL 的 userinfo 密码、`Password` 值进入 `secrets []string`，用于 `Status.LastError` 与日志的二次脱敏。

### 4.3 连接生命周期状态机

状态：

- `closed`：终态；由 `Close` 设置。
- `connected`：当前 `transport != nil` 且 paho 连接可用。
- `connecting`：`run` 正在 dial/等待 CONNACK。
- `waiting`：退避 timer 等待下一次尝试。

`New` 的行为：

1. 完成 §4.2 的全部校验；
2. 构造 `Channel`，初始 `Status{Connected:false, LastError:"", ChangedAt: clock.Now()}`；
3. 启动唯一 `run` goroutine；
4. **不等待首次连接**，立即返回。理由：边缘设备可能在云端不可达时启动；REQ-CACHE-01/02 要求断线期间仍能运行并把事件交给缓存层；若 `New` 阻塞/失败，进程无法进入采集循环。

`run` 的主循环：

```text
attempt = 0
loop:
  if closed: return
  tr, err := dialer.Dial(connectCtx, cfg)
  if err:
     setStatus(false, err)
     log warn(attempt, backoff)
     delay = backoff(attempt)
     sleep via Clock.NewTimer(delay), select closed
     attempt++
     continue
  setStatus(true, "")
  attempt = 0
  subscribeRegistered(tr)          // SUBACK；失败只记 LastError/日志，不撕连接
  select:
    case err := <-tr.Lost():       // paho OnConnectionLost
       setStatus(false, err); tr.Close()
    case <-closedCh:
       tr.Close(); return
```

要点：

- 连接成功后 `attempt` 归零；若连接立刻又断，下一次退避从 `min` 开始（flapping 的已知代价，见 §10）。
- `dialer.Dial` 接收 `context.Context`；`Close` 取消该 ctx，避免 `Close` 被一次网络 dial 拖住。paho 的 `Connect()` 返回 token 后，适配层用 `select { token.Done(), ctx.Done() }` 等待；ctx 取消时**不**对“仍在 connecting”的 paho client 调 `Disconnect`（paho 在 connecting 状态可能等待 CONNACK 完成），直接丢弃该 client；paho 内部 goroutine 最多到 `connectTimeout` 结束。
- 每次连接尝试创建**新的 paho Client**（而不是复用同一个 client）。理由：`CleanSession=true` + 新 client 使本地 router/订阅状态与 broker 会话一起清空，重连后只由我们显式重订阅，不会残留已关闭 filter 的 route；也避免 paho 断线后状态机的复用细节。
- `Channel` 的 `mu` 保护 `closed`、`transport`、`subs`、`status`；调用 `transport` 的网络方法时不持锁。
- `transport.Lost()` 由 `OnConnectionLost` 非阻塞投递（容量 1，重复丢失丢弃后来的 error）；回调不得阻塞 paho 的 goroutine。

### 4.4 MQTT 连接参数（client id、clean session、KeepAlive、QoS、TLS）

| 项 | 决定 |
|---|---|
| 协议版本 | MQTT 3.1.1（paho `SetProtocolVersion(4)`） |
| Client ID | `topics.Render(ClientIDTemplate, {"node.id": NodeID, "node_id": NodeID, "product_key": ProductKey})`；默认 `collector-{node.id}` |
| Clean Session | `true`；`ResumeSubs=false` |

| ConnectRetry | `false`；避免 paho 内部 sleep 与我们的假时钟竞争 |

| KeepAlive | `KeepaliveS` 秒 → `SetKeepAlive(time.Duration(s) * time.Second)`；paho 内部用真实定时器发 PINGREQ。**这是协议层 liveness，不是业务超时**；假时钟不进入 paho。KeepAlive=0 时禁用并发 warn。 |
| 连接超时 | 软件常量 `connectTimeout=10s`（`SetConnectTimeout`）；用于约束首次 dial 与 `Close` 的最坏等待。不是配置键，不是硬件值。 |
| 写超时 | 软件常量 `writeTimeout=5s`（`SetWriteTimeout`）；约束 paho 在 outbound 队列满时的 `Publish`/`Subscribe` 内部等待。 |

| TLS scheme | `tls.enabled=true` 且 broker scheme 为 `mqtt://`/`tcp://` 时，规范化为 `ssl://`；`tls.enabled=false` 且 scheme 为 `ssl://`/`tls://`/`mqtts://` 时构造错误（拒绝静默降级）。paho 的 `mqtt` scheme 不会应用 TLSConfig，因此必须规范化。 |
| 凭据 | `SetUsername`/`SetPassword` 仅在 `Username` 非空时设置；broker URL userinfo 由 paho 覆盖 options 凭据（源码行为），警告两者同时存在。日志/Status 二次脱敏。 |

### 4.5 节点级 LWT（topic / retain / payload 精确值）

- topic：`topics.RenderTopic(WillTopicTemplate, vars)`。
  - 默认模板：`v1/{product_key}/$nodes/{node_id}/state`。
  - 非默认测试：`custom/v2/{product_key}/nodes/{node_id}/offline` + `product_key=farm-a` + `node_id=gateway-001` → `custom/v2/farm-a/nodes/gateway-001/offline`。
  - `$nodes` 是字面量，不是占位符；渲染器只识别 `{...}`。
- payload：固定结构，字段顺序 `online`、`node_id`：
  - `{"online":false,"node_id":"gateway-001"}`。
  - 用 `json.Encoder` + `SetEscapeHTML(false)` 生成，去掉末尾换行；测试逐字节断言。
  - 该 payload 只表示 MQTT 连接断开；设备级离线仍由 `device_offline` 事件与属性 `online` 表达（`REQ-EVENT-03`、`EXT-LWT-01`）。
- retain：**推荐 false**（Q5）。契约未定义“在线”消息；retain=true 而没有在线 counterpart 会让晚订阅者永久看到离线状态。若用户要求 retain=true，必须同时定义在线状态消息并走 spec-delta（Q5=B）。
- QoS：`Options.QoS`（默认 1；配置 V45 保证 0/1）。
- 构造时机：`New` 时渲染并校验；paho 在每次 CONNECT 时携带。`Close` 走 graceful DISCONNECT，不触发 LWT；只有异常断开（broker 踢、网络断、KeepAlive 超时）才触发。
- client id 与 LWT 的关系：LWT 绑定到 CONNECT 的 client id；同 client id 的 takeover 会让 broker 为旧连接发 LWT（mochi 行为）。测试使用唯一 client id，避免串扰。

### 4.6 重连退避、抖动、重订阅与并发

退避：

- `min`/`max` 来自 `northbound.mqtt.reconnect.min_backoff_s`/`max_backoff_s`（默认 1 s / 30 s）。
- `base(n) = min * 2^n`，封顶 `max`；`n` 从 0 开始，连接成功后归零。
- 确定性抖动：
  - `jitter(n)` 由 `fnv64a(clientID + "\x00" + strconv.Itoa(n))` 映射到 `[0,1)`；
  - `delay = base/2 + jitter*base/2`，再 clamp 到 `[min, max]`；
  - 这样首次重试为 `min`，之后在 `[min, 2min]`、`[2min, 4min]`… 内抖动，且永不超过 `max`。
  - 不引入 `math/rand` 全局状态；同一节点、同一 attempt 的延迟可复现，避免整批边缘设备同时重连。
- 实现使用 `interfaces.Clock.NewTimer(delay)` + `select { timer.C(), closedCh }`；不使用 `Clock.Sleep`（Close 无法打断）。退出前 `timer.Stop()`。
- 测试用同包 unexported `jitterFunc` 注入固定 0 / 0.5 / 0.999，断言精确 delay；生产用 FNV 版本，测试其范围/封顶/确定性。

重订阅：

- `Channel` 维护 `subs map[string]*subscription`（一个 filter 一个订阅；重复 `Subscribe` 返回错误，见 §4.8）。
- 连接成功后，`subscribeRegistered(tr)` 对每个已登记 filter 调 `transport.Subscribe(ctx, filter, Options.QoS, sub.deliver)`，等待 SUBACK。
  - paho 的 `SubscribeToken.Result()[filter] == 0x80` 表示 broker 拒绝；paho 不一定设置 token error，必须显式检查。
  - 单条 SUBACK 失败只更新 `Status.LastError` 并记日志；不撕连接；下一次重连再试。
  - `Subscribe` 与 `subscribeRegistered` 用一个 `subOpMu` 串行化 SUBACK 操作，避免同一 filter 被并发 SUBSCRIBE 两次。
- 连接丢失后，旧 transport 丢弃；新 transport 重新订阅全部 filter；旧订阅对象的 `C()` 不关闭（它们跨连接存活），继续接收新连接的消息。
- `Subscription.Close()` 只做本地注销/关闭通道；不发送 UNSUBSCRIBE（v0.1 取舍，见 §4.8）。新连接不再重订阅已关闭的 filter。

并发：

- `mu` 保护状态；`subOpMu` 串行 SUBACK；`subscription.sendMu` 保护“投递 vs 关闭”的竞态。
- `Publish` 只快照 `transport` 指针，不持锁等待；`Close` 可并发关闭 transport，paho 会把在途操作返回错误。
- `Status()` 加锁复制，不返回内部引用。

### 4.7 Publish 语义（断线快速失败、typed error、不阻塞、不 panic）

顺序：

1. `closed` → `fmt.Errorf("mqtt channel: %w", interfaces.ErrClosed)`（终态优先）。
2. `msg.QoS > 1` → `fmt.Errorf("mqtt channel: qos %d: %w", msg.QoS, interfaces.ErrUnsupported)`。
3. topic 校验（非空、无 wildcard、无 NUL、UTF-8、≤65535、不以 `$SYS/` 开头）→ plain error。
4. 复制 `msg.Payload`（paho 可能异步写/重试；调用方可在返回后复用缓冲区）。
5. 快照 `transport`；为 nil 或 `Connected()==false` → **立即** `fmt.Errorf("mqtt channel: publish %q: %w", topic, interfaces.ErrNotConnected)`。不等待重连、不排队、不 sleep。
6. 调 `transport.Publish(ctx, msg)`：
   - paho 适配层先检查 `client.IsConnected()`；未连接直接映射为 `interfaces.ErrNotConnected`；
   - 已连接时调用 paho `Publish`，然后 `select { <-token.Done(), <-ctx.Done() }`；
   - QoS0 在 paho 完成写队列/写出后返回；QoS1 在 PUBACK 后返回；
   - `ctx` 为 nil 时使用 `context.Background()`；不使用 `context.WithTimeout`；
   - token error 为 paho `ErrNotConnected` → 映射 `interfaces.ErrNotConnected`；`closed` → `ErrClosed`；其他错误原样 `%w` 包装（保留网络错误细节，便于日志）。
7. 不因单次 Publish 失败改写 `Status`；连接丢失由 `Lost()` 回调统一更新。若错误是 `ErrNotConnected` 且状态仍显示 Connected，适配层可调用一次 `markDisconnected`（只在状态翻转时更新 `ChangedAt`），避免状态长期滞后。

“不阻塞”的口径：

- **断线时**：状态检查 + paho `Publish` 的 `ErrNotConnected` 立即返回（本地实测约 54 µs）；不等待重连。
- **已连接但 broker 不 ACK 时**：QoS1 会等待 PUBACK，最多由调用方 `ctx` 取消；paho 的 outbound 入队受 `writeTimeout=5s` 约束。这是“可靠的发布”与“不阻塞”的边界，计划如实写明。
- 不 panic：所有错误路径返回 error；`ctx` 为 nil、通道已关闭、并发 Publish/Close 都有测试。

### 4.8 Subscribe / Subscription / 背压 / 关闭语义

`Subscribe(ctx, filter)`：

1. `closed` → `ErrClosed`。
2. `topics.ValidateFilter(filter)`；非法 → plain error。
3. 重复 filter → 返回错误（一个 filter 一个订阅；避免同一 filter 双订阅造成重复投递/重复 SUBSCRIBE）。调用方应合并自己的 filter 集。
4. 创建 `subscription`：`ch := make(chan interfaces.Message, subscribeBuffer)`（建议 16）、`done chan struct{}`、`sync.Once`、`sendMu sync.RWMutex`；登记到 `subs`。
5. 若当前已连接：在 `subOpMu` 下调用 `transport.Subscribe(ctx, filter, Options.QoS, sub.deliver)`；失败则注销/关闭并返回错误。
6. 若未连接：登记后立即返回订阅对象；连接成功后由 `subscribeRegistered` 建立；SUBACK 失败通过 `Status.LastError`/日志暴露，不阻塞 `Subscribe`。
7. `ctx` 非 nil 时启动一个 watcher goroutine：`select { <-ctx.Done(): sub.Close(); <-sub.done: }`；ctx 为 `Background()` 时 `Done()==nil`，watcher 只等 `sub.done`，不会泄漏。

`Subscription`：

- `C()` 返回只读通道；消费者应用 `msg, ok := <-C()` 判断通道已关闭。
- `Close()` 幂等：
  1. `once.Do(close(done))` 先解除阻塞的投递；
  2. 从父 `subs` 删除；
  3. `sendMu.Lock()` 后关闭 `ch`，保证没有并发 send；
  4. 返回 nil。
- 不发送 UNSUBSCRIBE：本地关闭即可满足“关闭后不再投递”；broker 可能继续发送到同一 filter，但 `deliver` 看到 `done` 会丢弃。原因是避免 `Close` 因网络往返而阻塞；05b 的 filter 数量很小，额外流量可接受。若未来需要降低 broker 流量，再单独评审。
- 通道 `Close()` 会关闭所有订阅通道。

投递/背压：

- paho 的 router 回调调用 `sub.deliver(msg)`；`deliver`：
  - 若 `done` 已关闭，直接丢弃；
  - 复制 payload；
  - `sendMu.RLock()`；`select { case ch <- msg: case <-done: }`；`RUnlock`。
- 这样是**有界缓冲 + 阻塞背压**（Q9=A）：不丢消息、不无限增长；慢消费者会阻塞 paho 的 inbound router（`OrderMatters=true`），进而延迟 QoS1 ACK、让 broker 重试。恢复手段是消费者尽快读取或 `Close` 订阅。
- 若用户选择 Q9=B（非阻塞丢弃），则改为 `select` default 丢弃并计数/日志；本计划默认不采用，因为下行服务调用不应静默丢失。
- paho 的 `AutoAckDisabled=false`（默认）：handler 返回后自动 ACK；阻塞即背压。
- 入站 QoS2：正常情况不会出现（订阅 QoS≤1，broker 会降级）；若出现，丢弃并记 warn，不把 `QoS(2)` 传给调用方（接口只有 0/1）。
- `DedupKey` 留空；由 05b/11 决定。

### 4.9 Close 语义、幂等与错误优先级

- `Close()`：
  1. `mu` 下若已 closed，跳到等待完成；否则置 closed、`close(closedCh)`、快照当前 transport 与订阅；
  2. 取消连接 ctx（打断 dial/SUBACK）；
  3. 关闭所有订阅（幂等）；
  4. 若 transport 已连接，调 `transport.Close()`（paho `Disconnect(0)`，best effort）；若仍在 connecting，只丢弃，不调 `Disconnect`（避免 paho 在 connecting 状态等待）；
  5. 等待 `runDone`（`Close` 的每次调用都等待同一个完成信号），然后返回；
  6. 设置 `Status{Connected:false, LastError:"channel closed", ChangedAt: clock.Now()}`。
- 幂等：所有 `Close` 调用都返回 nil（transport 关闭错误只记日志）；并发 `Close` 不会重复关闭/panic。
- 错误优先级：`closed` > `not connected` > 其他。`Publish`/`Subscribe` 在 Close 后返回 `ErrClosed`。
- 在途 `Publish`：`Close` 关闭 transport 后，paho token 返回错误；`Publish` 返回 `ErrClosed`（若已观察到 closed）或底层错误；不等待调用方、不死锁。测试覆盖。
- `Close` 可能等待一次正在进行的 `dial`；生产由 `connectTimeout=10s` 封顶；测试用尊重 ctx 的假 dialer 证明快速返回。

### 4.10 Topic 模板与 `internal/topics`

API：

```go
func Render(tmpl string, vars map[string]string) (string, error)
func RenderTopic(tmpl string, vars map[string]string) (string, error)
func ValidatePublishTopic(topic string) error
func ValidateFilter(filter string) error
```

规则：

- 占位符语法 `{name}`；`name` 非空，允许字母/数字/`_`/`.`；未知占位符、空 `{}`、不配对 `{`/`}` → error。
- `Render`：替换值原样使用；值必须 UTF-8、非空、无 NUL；用于 client id 和 05b 自行构造 filter。
- `RenderTopic`：在 `Render` 基础上：
  - 替换值不得含 `/`、`+`、`#`、NUL（防止设备 SN 改变 topic 层级/注入通配符）；
  - 结果必须通过 `ValidatePublishTopic`：非空、UTF-8、≤65535 字节、无 `+`/`#`、无 NUL、无空 level（`//`、首尾 `/`）、不以 `$SYS/` 开头。
- `ValidateFilter`：非空、UTF-8、≤65535；`#` 只能作为最后一级且独占该级；`+` 必须独占一级；无 NUL；允许空 level？拒绝空 level，避免配置错误。
- 模板来源是配置/`Options`，代码中只有默认值文档，不把 `v1/...` 或 `$nodes` 写进通道逻辑。测试用非默认前缀/`product_key` 证明。
- 占位符映射：
  - `product_key` → `ProductKey`
  - `device_sn` → 设备 SN（05b）
  - `node_id` / `node.id` → `NodeID`
  - `event_id` → 事件 ID（05b）
- client id 用 `Render`，topic 用 `RenderTopic`；05b 的 filter 用 `Render` + `ValidateFilter`（允许通配符由 05b 决定）。

### 4.11 状态、日志与凭据

- `Status()` 返回 `ChannelStatus` 的副本；`ChangedAt` 全部来自 `Clock.Now()`：
  - 构造：false/""/now；
  - 连接成功：true/""/now；
  - 连接失败或丢失：false/脱敏后的错误文本/now；
  - 重订阅失败：保持 Connected=true，更新 LastError/ChangedAt（连接仍在，但订阅不完整）；
  - Close：false/"channel closed"/now。
- 日志：注入 `*slog.Logger`；nil 时用 `io.Discard` 的 JSON logger（测试安静，不污染 stdout/stderr）。
  - 字段：`component=mqtt`、`event=connect|disconnect|reconnect_scheduled|subscribe|publish_failed|closed`、`broker`（去掉 userinfo）、`client_id`、`attempt`、`backoff_ms`、`reason`；不打印 username/password/token/payload。
  - `broker` 脱敏：`scheme://[REDACTED]@host`（有 userinfo 时）。
  - `Status.LastError` 与日志文本二次替换 `secrets`（Password、broker userinfo password）为 `[REDACTED]`。
  - paho v1.5.1 的全局 logger 默认是 NOOP；不打开 paho debug，避免绕过脱敏。
- `Secret` 类型实现 `String()`/`GoString()` 返回 `[REDACTED]`；测试用 `fmt.Sprintf("%#v", opts)` 断言不泄漏。

### 4.12 资源、goroutine 与生命周期

| 资源 | 数量/生命周期 | 关闭方式 |
|---|---|---|
| `run` goroutine | 每 Channel 1 个 | `Close` 关闭 `closedCh`；等待 `runDone` |
| paho client/transport | 每次连接尝试 1 个 | 成功：断线/Close 时 `Close`；失败：丢弃（connecting 状态不调 Disconnect） |
| 退避 timer | 同时最多 1 个 | `Close` 取消 select；退出前 `Stop` |
| subscription ctx watcher | 每个带有效 ctx 的订阅 1 个 | `sub.Close()`/Channel Close 关闭 `done` 使其退出 |
| 订阅消息缓冲 | 每订阅 `subscribeBuffer=16` 条 | Close 关闭通道 |
| paho 内部 goroutine | paho 管理 | 断线/Disconnect 后由 paho 停止；connecting 取消时最多到 `connectTimeout` |

- 不 per-message 起 goroutine；不无界队列。
- `Publish` 不持 `mu` 等待网络；`Close` 不需要等所有调用方，只等 `run` 退出。
- 测试用 `Close` 返回作为“run 已停止”的证据；不引入 `goleak` 依赖。`-race -count=10` 覆盖并发。

### 4.13 软件常量（不是硬件 ASSUMED）

| 常量 | 值 | 理由 |
|---|---|---|
| `connectTimeout` | 10 s | 约束首次 dial/Close 最坏等待；paho 默认 30 s 太长 |
| `writeTimeout` | 5 s | 约束 paho outbound 入队等待 |
| `subscribeBuffer` | 16 | 有界背压；与服务调用突发量匹配 |
| MQTT 最大 topic/字符串长度 | 65535 字节 | 协议限制 |
| 退避抖动哈希 | FNV-1a | 确定性、无全局随机状态 |
| LWT retain | 推荐 false | 契约决策，见 Q5；不是硬件值 |

这些是软件安全边界，不写入 `docs/缺口台账.md` 的硬件 `ASSUMED` 表；若用户希望可配置，需新增配置键并走 spec-delta（Q13）。

## 5. MQTT 客户端选型（一级决策）

### 5.1 候选

| 选项 | 说明 |
|---|---|

### 5.2 评估矩阵

| 维度 | A paho 自动重连 | **B paho 显式循环** | C 自研 | D 其他 |
|---|---|---|---|---|
| 静态编译 | 纯 Go，可 `CGO_ENABLED=0` | 同 A | 可控 | natiu 零依赖；gomqtt 纯 Go；paho.golang 纯 Go |

### 5.3 推荐

**推荐 B：paho + `AutoReconnect=false` + 仓库内显式循环。**

理由：

1. 连接/重连/重订阅是我们必须验收的行为；显式循环让退避、状态、Subscribe 顺序都能用注入 Clock 和假 transport 做确定性 L1，不依赖 paho 内部真实定时器。
2. paho 负责协议正确性（CONNECT/CONNACK、QoS1 PUBACK、PINGREQ/PINGRESP、LWT、TLS），避免自研协议栈在 v0.10 范围内引入不可接受的风险。
3. 本地临时模块实测（2026-11-23）：
   - paho v1.5.1 在 `CGO_ENABLED=0 GOOS=linux GOARCH=arm64/amd64` 下均静态编译成功；
   - `AutoReconnect=false` + `ConnectRetry=false` 时，broker 踢掉连接后 `OnConnectionLost` 触发；断线时 `Publish` 约 54 µs 返回 `not Connected`；同一 client 再次 `Connect` 成功，新建 client 也成功；
   - 对 mochi v2.7.9 实测 LWT：topic/payload/QoS/retain 与 CONNECT 的 will 完全一致（payload 逐字节），异常断开触发；源码核对 graceful DISCONNECT 会清空 Will（`server.go` 的 `cl.Properties.Will = Will{}` 分支），L2 将实测抑制。
4. A 的自动重连退避在 paho 内部，使用真实时间，无法用假时钟确定性测试，且 `ConnectRetry` 会引入内部 sleep；与 REQ-TIME-01 的精神和 L1 可测性冲突。
5. C 自研需要自己实现 QoS1 重传、会话、KeepAlive、LWT、TLS 边界，测试与维护成本远高于本 ticket；06b 的测试客户端只覆盖测试所需子集，不能当生产实现。
6. D 中 `natiu-mqtt` 是最有价值的备选（MIT、零依赖、3.1.1、可注入 `Nanotime`、context 友好），但它是低层库：需要自己实现读循环、KeepAlive 调度、QoS1 orchestration 与重连；作为 05a 的备选会增加实现面。`gomqtt` 维护停滞且依赖重；`paho.golang` 只支持 MQTT v5，不适配当前 3.1.1 链路。若用户因许可/依赖政策拒绝 paho，建议改用 natiu，并把本计划升级为 v2（工作量明显增加）。

## 6. 需要用户拍板的 A/B

> 推荐项加粗。未拍板前不进入实现。每项给出推荐、理由、影响面。

### 6.1 一级决策

**Q1 客户端选型（字母与 §5 的候选一致）**

- **B（推荐）**：paho v1.5.1 + `AutoReconnect=false` + 仓库显式循环。
- A：paho 自动重连，退避交给库。
- C：自研最小 MQTT 3.1.1 客户端。
- D：natiu-mqtt（MIT/零依赖，低层，需自写读循环/KeepAlive/重连）。
- 理由/影响：B 平衡成熟度与可测性；A 不可用假时钟确定性测退避；C 风险/成本最高；D 是 paho 被许可/依赖政策否决时的备选，需计划 v2。

**Q2 首次连接语义**

- **A（推荐）**：`New` 只校验并启动后台 `run`，不等待首次连接；断线时调用方立即得到 `ErrNotConnected`。
- B：`New` 同步连接，失败返回 error。
- 理由/影响：A 支持“云端不可达也要启动并缓存”；B 会让进程在断网时无法进入采集循环。A 要求 05b/16 正确处理启动初期的 `ErrNotConnected`。

**Q3 05a 是否接 `app`/`cmd` 的 `run`**

- **A（推荐）**：不接线；05a 只提供 `New(Options)`，由 05b/07 装配。
- B：05a 就在 `run` 构造并启动通道。
- 理由/影响：目前没有消费者（适配器/缓存未就绪），接线会产生无用的连接和未关闭 goroutine；A 的验收在包级测试完成，B 会把 05b/16 的装配问题提前混入本 ticket。若用户要求 `run` 立即连 MQTT，需把 05b/16 的最小消费路径纳入本 ticket，范围扩大。

**Q4 首次连接前 `Subscribe` 的语义**

- **A（推荐）**：登记 filter 并返回 Subscription；连接成功后自动建立；SUBACK 失败通过 Status/日志暴露。
- B：未连接时 `Subscribe` 返回 `ErrNotConnected`，调用方自行重试。
- 理由/影响：A 允许启动时先注册下行 filter、后连上云；B 需要调用方实现重试并可能与通道的内部重连重复。A 要求调用方接受“已返回订阅但 SUBACK 尚未确认”的窗口。

### 6.2 LWT 与 Topic

**Q5 LWT retain 形态**

- **A（推荐）**：`retain=false`。严格按 `EXT-LWT-01` 只表达“连接断开”；不新增在线消息。
- B：`retain=true`，并在每次成功连接时向同一 topic 发布 `{"online":true,"node_id":"..."}`（retained）。这会新增契约未定义的在线状态消息，需先开 `spec-delta/lwt-online-state`，更新 `EXT-LWT-01` 后再实现。
- C：`retain=true` 但不发在线消息。**不推荐**：晚订阅者会永久看到离线。
- 理由/影响：A 最小、无需规范变更；B 对云端更友好但需要用户批准契约变更并等 spec-delta 合并；C 会产生错误状态语义。ticket 的“retain 精确断言”在 A/B 下都可测。

**Q6 LWT QoS 来源**

- **A（推荐）**：使用 `northbound.mqtt.qos`（默认 1）。
- B：LWT 固定 QoS1，忽略配置 qos。
- 理由/影响：A 与配置语义一致；若用户把 qos 设为 0，LWT 也降为 0（可能丢失）。B 更可靠但引入一个与配置不一致的隐式例外。

**Q7 Topic 模板归属**

- **A（推荐）**：新增 `internal/topics` 纯函数小包；05a 用于 LWT/client id，05b 用于上行/下行 topic 与 filter。
- B：渲染器放在 `internal/channels/mqtt`，05b 复用具体通道包（适配器→通道耦合）。
- C：适配器各自渲染，通道只接收已渲染的 LWT topic；05a 仍需渲染 client id/topic，容易重复。
- 理由/影响：A 让模板规则只有一个实现，避免 05b 重复/漂移；新增一个小包，不改变依赖方向。B 破坏适配器与通道的解耦；C 会让 LWT/客户端 ID 的模板逻辑分散。

**Q8 重连抖动**

- **A（推荐）**：确定性 equal jitter（FNV(clientID+attempt)），范围 `[base/2, base]` 并 clamp 到 `[min,max]`；无全局随机状态。
- B：纯指数退避，无抖动。
- C：`math/rand` 随机抖动，测试注入随机源。
- 理由/影响：A 避免整批节点同时重连，且测试可复现；B 简单但可能造成重连风暴；C 需要额外注入/测试设施。A 的退避永不小于 `min`，首次重试仍是 `min`。

### 6.3 运行时语义与工程

**Q9 订阅投递背压**

- **A（推荐）**：每订阅 16 条有界缓冲；满时阻塞投递（`select` 兼顾 `done`），`Close` 解除阻塞；不丢消息。
- B：满时非阻塞丢弃并计数/日志。
- C：无界队列（不允许，违反有界内存）。
- 理由/影响：A 保护下行服务调用不静默丢失；慢消费者会阻塞 paho inbound（延迟 ACK），这是可观测的背压。B 简单但可能丢指令。A 要求 05b 的消费者的读取循环足够快；否则调用方应 Close 订阅。

**Q10 Clock 注入与静态检查范围**

- **A（推荐）**：`internal/channels/mqtt` 注入 `interfaces.Clock` 用于 `Status.ChangedAt` 与退避 timer；把 `internal/channels` 加入 `scripts/check-time.sh` 的 roots，静态禁止直接 `time.*`/`context.WithTimeout`。
- B：注入 Clock，但不扩大 check-time 范围。
- C：通道直接用真实时间（不注入 Clock）。
- 理由/影响：A 把 REQ-TIME-01/ADR-0003 的规则扩展到通道，防止未来回退；协议 KeepAlive 仍在 paho 内用真实时间（明确边界）。B 可测但无静态保障；C 与仓库时间纪律冲突。A 会改变 CI 检查范围（仅新增 `internal/channels`）。

**Q11 TLS scheme 处理**

- **A（推荐）**：`tls.enabled=true` 时把 `mqtt://`/`tcp://` 规范化为 `ssl://`；`tls.enabled=false` 时遇到 `ssl://`/`tls://`/`mqtts://` 构造错误；`ca_file`/`insecure_skip_verify` 在未启用 TLS 时报错。
- B：要求运维直接写 `ssl://`，通道不改写；scheme 与 enabled 不一致时仍报错。
- C：忽略不一致，按 scheme 决定（可能静默明文）。
- 理由/影响：paho 的 `mqtt` scheme 不应用 TLSConfig（源码事实），A 避免“配置了 TLS 却明文连接”的高危错误；B 更显式但增加配置负担；C 不可接受。

**Q12 独立测试客户端复用**

- **A（推荐）**：把 06b 的独立 MQTT 3.1.1 测试客户端抽取为 `internal/testutil/mqttclient`（非 `_test.go`，仅测试 import），06b 与 05a 测试共用；06b 测试做机械 import 调整，行为不变。
- B：在 05a 测试中复制/另写一份最小客户端，不改 06b 测试。
- 理由/影响：A 避免 ~300 行重复，且证明测试依赖不进入生产闭包；会触碰 06b 的测试文件（只是重构，不改行为）。B 零 06b 改动但重复代码，后续两边漂移。A 需要在 `check-deps.sh` 断言 `internal/channels` 生产闭包不含 `internal/testutil`。

**Q13 配置校验一致性**

- **A（推荐）**：05a 只在通道构造器校验 `keepalive_s`/`reconnect`/TLS/模板；`config-check` 维持现状。`run` 在通道构造失败时返回清晰错误并退出。
- B：在 05a 同时给 `internal/config` 增加 V46/V47 规则（keepalive/reconnect），使 `config-check` 与 `run` 一致；需要更新 `rules.go`、`validate.go`、单测/golden，并可能触碰 `docs/contracts/config.md` 的规则分类（普通 feature 分支不得改 contracts）。
- 理由/影响：A 保持 ticket 范围；B 更一致但扩大 diff，且若要把新规则写入合同，需要 spec-delta。推荐 A，把 B 记为后续 ticket。

**Q14 重复 filter 的 `Subscribe`**

- **A（推荐）**：一个 filter 一个订阅；重复 `Subscribe` 返回错误。
- B：允许多个订阅对象共享同一 filter，向每个对象 fan-out。
- 理由/影响：A 简单、避免重复 SUBSCRIBE 与重复投递；B 提供更大灵活性但增加路由/关闭复杂度。05b 预期每个 filter 只订阅一次。

## 7. 测试策略

### 7.1 分层

| 层 | 范围 | 时间 | 依赖 |
|---|---|---|---|
| L1 单元 | 模板渲染、Options 校验、状态机、退避、LWT 构造、Publish/Subscribe/Close、脱敏 | 假时钟（fakeclock） | 假 dialer/假 transport（仅 `_test.go`） |
| L2 集成 | 真实 paho + 06b 内嵌 broker：连接、KeepAlive、LWT、断线/重连、重订阅、真实 typed error | 真实时钟 + 有界等待 | `internal/sim`、独立 MQTT 客户端 |
| L3/L4 | 真实二进制 + 24 小时稳定性 | 真实时钟 | 07/发布门禁，不属于 05a |

`docs/testing.md` 的 L2 行提到“通道重连”使用假时钟；本计划的边界是：**退避/状态机的确定性部分在 L1 用假时钟；真实 socket 的重连在 L2 用真实时钟和有界等待**。这不是降低验收，而是把可确定性测试放在能注入时间的一层；L2 保留真实 paho/broker 的端到端证据。若评审要求 L2 也必须假时钟，则只能改用假 transport，失去真实 socket 覆盖，不推荐。

### 7.2 L1 用例清单（`internal/channels/mqtt` 同包测试 + `internal/topics`）

| ID | 场景 | 断言 |
|---|---|---|
| L1-01 | `New` 空/非法 Options | nil Clock、空 broker、坏 scheme、空 ClientID/NodeID/ProductKey、QoS2、min≤0、max<min、坏 CA、password 无 username、TLS 未启用却有 ca_file 均返回 error |

| L1-04 | 首次连接失败 + 退避 | 假 dialer 失败；假时钟逐步推进；断言 delay 序列、封顶、抖动注入、Close 停止 timer |

|---|---|---|
| L2-01 | 连接并发布 QoS1 | sim `/_sim/captured` 收到 exact topic/payload/qos/retain；Status Connected |
| L2-02 | KeepAlive | `KeepAlive=1s`；空闲 2.5 s 后仍 Connected（broker 未按 1.5×keepalive 断开） |
| L2-03 | LWT 精确 | 独立订阅者订阅 LWT topic；`broker_disconnect` 后收到 exact topic、payload 字节、retain、QoS |
| L2-04 | graceful Close 不发 LWT | Close 后短时间内独立订阅者无 LWT |
| L2-05 | 重连 + 重订阅 | `broker_disconnect`（duration=0）→ 等 Connected → 独立客户端/HTTP 注入下行 → 通道订阅收到 |
| L2-06 | 保持期拒绝 | `broker_disconnect` duration 使 CONNECT 被拒；Publish 返回 ErrNotConnected；保持期结束后自动恢复 |
| L2-07 | 并发 Publish 断线 | 保持期内并发 Publish，全部有界时间返回 typed error，无 panic |
| L2-08 | 非默认模板 | 自定义 `adapter.topics.node_state` + `product_key`，L2-03 仍精确 |
| L2-09 | 无 TLS 的 broker | 仅验证 `tls.enabled=false` 走 `mqtt://`；TLS 握手不在 06b 范围（L1 覆盖配置） |

L2 等待策略：

- 使用 `127.0.0.1:0` 临时端口、每测试独立 runtime/broker、唯一 client id。
- 用 `t.Cleanup` 关闭 broker/runtime/channel；`Close` 后再断言端口释放。
- 用 3 s 上限的轮询 helper（`Status().Connected`、捕获条件、订阅读取）；不用固定长 sleep。
- L2 的退避用较短的 Options（如 20 ms/100 ms）以缩短测试；配置默认 1 s/30 s 的精确行为由 L1 假时钟断言。

### 7.4 假时钟与真实时钟边界

- 假时钟覆盖：`Status.ChangedAt`、退避 timer、重连尝试顺序、Close 打断 timer。
- 真实时钟覆盖：paho 的连接/KeepAlive/PUBACK、真实 socket 断线、broker 保持期。
- 不尝试把 fakeclock 注入 paho；paho 的 KeepAlive/ConnectTimeout 是其协议实现的一部分。
- fakeclock 的“step, do not jump”文档要求：测试逐步 `Advance` 到下一次预期 dial，并等待假 dialer 记录；不要一次跳大时长。

### 7.5 race、重复与 goroutine 泄漏

- `go test -race -count=10 ./internal/topics ./internal/channels/mqtt`（L1 可重复）。
- L2 单独 `go test -race -count=3 ./internal/channels/mqtt -run 'TestL2'`；若时间敏感，`-count=1` 并在 PR 说明。
- 并发用例：Publish/Subscribe/Close/Status 交错；断言不 panic、无负计数、通道最终关闭。
- goroutine 泄漏：不引入 `goleak`；以 `Close` 返回（runDone）和 `-race -count` 作为证据；L1 的假 transport 记录未完成的 goroutine 数（测试内部计数）并在 Close 后断言为 0。paho 内部 goroutine 由 paho 管理，L2 通过重复运行观察。
- 所有测试注释标注覆盖的 `REQ-*`/合同锚点，例如 `// Covers: REQ-TIME-01, EXT-LWT-01`。

## 10. 风险与回退

| 风险 | 影响 | 缓解/回退 |
|---|---|---|
| paho 许可/依赖政策不接受（EPL/EDL、x/net/x/sync） | 可能需要换客户端 | Q1=D natiu（MIT/零依赖），计划 v2；或自研（不推荐）。在实现前由用户拍板 |
| paho 显式重连状态机不如 AutoReconnect 成熟 | 重连回归 | 本地实测同 client/新 client 均可重连；L1 假 transport + L2 真实 broker 双覆盖；若发现 paho 状态机问题，改为每次连接新建 client（本计划已倾向新建） |
| paho 在 connecting 状态 `Disconnect` 可能等待 | Close 变慢 | connecting 取消时只丢弃 client，不调 Disconnect；`connectTimeout=10s` 封顶；测试用尊重 ctx 的假 dialer |
| LWT retain 选择与云端期望不一致 | 云端离线状态不对 | Q5 由用户拍板；若选 B，先走 spec-delta 增加在线消息 |
| 慢订阅者阻塞 paho inbound | 下行延迟/ACK 延迟 | Q9=A 的有界背压；调用方尽快读取或 Close；必要时切 Q9=B（丢弃+计数） |

| L2 真实时钟测试抖动/flaky | CI 不稳定 | 临时端口、唯一 client id、有界轮询、较短退避；L1 覆盖确定性部分；必要时 `-count=1` |
| `go mod tidy` 升级 gorilla/websocket | 间接依赖 Diff | 锁定 paho v1.5.1；`make verify-static` 双架构；license 记录 |

| 04a plan 缺失 | 结构参考不足 | 已用 06b/02b；不阻断 |

## 11. 规范/合同影响判断

**推荐方案（A 选项）不需要 spec-delta。**

- `EXT-TOPIC-01`：模板来自配置，05a 只实现渲染/校验；不改变合同。

- `REQ-TIME-01`：通道用注入 Clock 取 `Status.ChangedAt`/退避；协议 KeepAlive 由 paho 的真实定时器承担，边界已在 §4.4 说明。若 Q10=A，`scripts/check-time.sh` 扩展到 channels。
- `REQ-SEAM-01`：通道只依赖 `interfaces`/`topics`/paho；内核不 import 具体实现；装配留给 05b/07。
- `REQ-QUALITY-01`：通道不改写 payload/quality；只复制字节。
- `REQ-EVENT-03`：LWT 只表示节点连接断开；设备离线不走 LWT。
- `REQ-CACHE-01/02`：05a 不缓存；断线时返回 `ErrNotConnected`，由 16a/16b 实现有界缓存/补发。
- `REQ-OPS-03`：通道日志 JSON、字段固定、凭据脱敏；不打印 payload。
- `REQ-OPS-02`：05a 不实现 health/metrics；18 消费 `Status()`。
- `CFG-RELOAD-01`：`northbound.mqtt.*` 与 `adapter.topics` 不可热重载；05a 不提供运行时重配。

3. 扩展 `Channel` 接口（例如 per-subscribe QoS、Close 状态）——接口冻结，需 spec/接口变更评审。

引用规范时使用 `REQ-*`，引用合同使用 `EXT-TOPIC-01`/`EXT-LWT-01` 等锚点；不使用 `spec §N` 作为跨文档指针。
