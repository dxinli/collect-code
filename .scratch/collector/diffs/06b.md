## 3. 运行时链路

```text
simulate CLI
  ├─ NewRuntime(http=127.0.0.1:0, capture)
  ├─ NewMQTTBroker(mqtt=127.0.0.1:0)  [绑定 listener]
  ├─ broker.Register(runtime)
  │    ├─ manifest.mqtt section
  │    ├─ endpoints: captured/invoke/control
  │    ├─ routes: GET captured, POST invoke（control 由 runtime 注册）
  │    ├─ control: global/broker_disconnect
  │    └─ inline Subscribe(filter)
  ├─ broker.Start()                  [mochi Serve]
  ├─ runtime.Start()                 [HTTP Serve]
  ├─ runtime.WriteManifest(path)     [原子写]
  └─ 等信号/ctx → HTTP Shutdown → broker Close
```

- 真实客户端 publish → mochi → inline 订阅回调 → 跳过 `$SYS/` 与 inline-origin → capture ring。
- `/_sim/invoke` → inline Publish → 真实订阅者；回调按 origin 跳过捕获。
- `broker_disconnect` → 设置 hold（可选）→ `Client.Stop` 踢非 inline 连接；下次 CONNECT 由 auth hook 按注入时钟判定。

## 4. 与计划的偏差（非契约）

1. **step 3 合入 step 2**：见 §1。
2. **mochi hook 在根包**：`HookBase`/`OnConnectAuthenticate`/`OnACLCheck` 属于 `github.com/mochi-mqtt/server/v2` 根包（别名 `mqtt`），不在 `hooks` 子包；计划中的 `hooks.` 前缀为笔误。实现与 spec §7.1 以根包为准。
3. `SetSection` 自动把 section 名加入 `modules`；`Runtime` 自动注册 control 路由；新增 `Capacity()` 方法供 manifest 使用。均为内部装配细节，不改变 CLI/HTTP/manifest 契约。
